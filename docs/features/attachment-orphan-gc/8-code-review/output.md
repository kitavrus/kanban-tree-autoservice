## Незначительные замечания (можно в следующем PR)
1. **[internal/filestore/orphans.go, `massGuardMin`] (информационно)** Предохранитель работает по принципу «всё или ничего».
   - Он не срабатывает, если в индексе найден хотя бы один ключ. Это частично чужая БД, например старый бэкап с небольшой долей совпадений.
   - Легитимное состояние «≥20 старых сирот, живых нет» (все вложения удалены, затем падения) навсегда блокирует удаление ключей и раз в период пишет Error в лог. Это задумано («каталог разбирает человек»), но в runbook или комментарии не описано, как разблокировать.
   - Вариант на будущее: порог по доле сирот и явный override через env.
2. **[internal/server/router.go:41-47]** Нет `ReadTimeout`/`IdleTimeout` при `StreamRequestBody`. Если клиент завис посреди загрузки дольше `UPLOADS_GC_MIN_AGE`, temp-файл удаляется, а загрузка отвечает 500 (данные не теряются). Оставлено осознанно как known issue: поведение as-is с фазы 7.
3. **[cmd/server/main.go:68]** Второй `filestore.NewLocal(cfg.UploadsDir)` дублирует `internal/server/router.go:150`. Оставлено осознанно: экземпляр stateless, а так wiring сборщика не зависит от router.

Закрыты LOW первого прохода:
- `UPLOADS_GC_INTERVAL`: разрешены только 0 или ≥1s. Кейсы в `config_test.go`: граница `1s`, отказ на `500ms`. `.env.example` обновлён.
- `logger` передаётся в `SweepOrphans`, пофайловое удаление логируется на уровне `Info` с именем ключа, глобальный `slog` не используется.
- `ExistingKeys`: `pgx.CollectRows(rows, pgx.RowTo[string])` и обёртка `%w`.

## Проверено (Slim-чеклист)
- **Security.**
  - Удаляются только канонические uuid-ключи и `.upload-*`.
  - Symlink и каталоги отсекаются (`IsRegular`).
  - Имена берутся из `ReadDir` и соединяются с абсолютным `dir` через `filepath.Join`.
  - Есть предохранитель от чужой или пустой БД.
  - Секретов и PII в логах нет; имя ключа — uuid, не имя пользователя.
- **Гонки.**
  - Идущая загрузка не задевается: порог `minAge` не меньше 1m, `rename` сохраняет mtime, `INSERT` идёт сразу после `Put`.
  - Параллельные `Delete`/`rename` уходят в ветку `ErrNotExist`.
  - Два blue-green инстанса безопасны: проход идемпотентен.
  - Теперь удаление начинается только после сверки всех пачек, поэтому окно между проверкой ключа и `Remove` длиннее. На корректность это не влияет: кандидат старше `minAge`.
- **Ошибка БД.** Ни одного удаления ключевых файлов. Покрыто тестами `TestSweepOrphans_IndexErrorKeepsKeys` и `TestSweep_DBUnavailableKeepsFiles`.
- **Architecture fit.**
  - Сборщик лежит в `internal/filestore` за интерфейсом `KeyIndex`.
  - Интерфейс реализует `AttachmentRepo.ExistingKeys`: запрос `= ANY($1)` по UNIQUE `storage_key`.
  - Запуск — в `cmd/server/main.go` на ctx сигналов.
- **Error handling.**
  - Ошибка прохода логируется, тикер продолжает работу.
  - Невалидный конфиг останавливает `Load()`.
  - Ошибки репозитория обёрнуты.
- **Tests.**
  - Unit: отбор файлов, каноничность ключа, граница возраста, ошибка индекса, пачки, предохранитель, отмена ctx, контракт `tempPrefix`, тикер, конфиг.
  - Integration (BaseSuite): 3 происхождения сирот, идемпотентность, БД недоступна.
  - LiveSuite: реальный бинарь, тикер 1s.
- **Rollback.** Миграций нет. Сборщик выключается `UPLOADS_GC_INTERVAL=0` без деплоя.
