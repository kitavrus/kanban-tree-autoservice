# Draft-spec decisions: Перемещения — отмена проведения и удаление (transfers-revert)

> Часть 6 из 6 мастер-спеки `transfers`. Вопросы пользователю по этой части отдельно не задавались:
> решения приняты в интервью мастера — `docs/features/transfers/draft-spec-decisions.md`.
> Номера DS и TS — мастер-идентификаторы.

## Откуда решения
- DS-017 — мастер-журнал, батч 3, В-12. DS-020, DS-021, DS-022 — батч 4 (В-15, В-16 и уточнение).
- DS-023, DS-025 — батч 5 (В-17, В-19). DS-050 — батч 7.
- DS-044, DS-053 — inferred мастера.

## Решения нарезки (2026-10-07)
- Запреты для единицы оборудования и архивирования склада (DS-026) реализованы в `transfers-core`; здесь — только документ и заказ.
- Общий 409 `CONFLICT` при удалении заказа с документами (часть 4) заменяется на `TASK_HAS_TRANSFERS` с номерами; отменённые документы перестают мешать удалению заказа.
- Значение `transfer_unreceive` в CHECK причин движений добавлено частью 4 (владелец DS-040); здесь оно начинает писаться.
- Детали, выведенные при написании (без отдельного DS): «более поздний документ» определяется по `received_at` (при равенстве — по id), а не по текущему местоположению единицы — иначе единица, которую увезли и вернули на тот же склад, обошла бы правило обратного порядка; при откате `sent_by` / `sent_at` сохраняются; строка с фактом 0 компенсирующего движения не даёт; сведения о последнем откате остаются на документе после повторной приёмки; тост `TASK_HAS_TRANSFERS` не скрывается автоматически; отменённый документ не восстанавливается.
- Вопрос для планирования (не для пользователя): удаление заказа выполняет пакет `board`, а документы принадлежат пакету `transfers` — кто выполняет SQL удаления отменённых документов в общей транзакции.
