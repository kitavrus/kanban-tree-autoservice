## Серьёзные замечания (исправить в этом PR)
1. **[web/ssr/_shared/js/transfers.js:44-48 `lineTotal`, :665-680 `updateAmount`]** Сумма строки в форме считается float'ом: `Math.round(p * q * 100) / 100`; сервер — `round(numeric, 2)` (half away from zero, точно). При дробном количестве расходится на копейку: 0.15 × 1.5 → сервер 0.23, форма 0.22; 0.10 × 0.35 → 0.04 / 0.03; 0.12 × 1.375 → 0.17 / 0.16. Перебор цена 0.01–30.00 × кол-во 0.001–3.000: 5967 расхождений из 9 млн; при целом количестве — 0. Комментарий :42-43 «сервер считает так же» неверен. Затронуто только превью редактора заявки, но `renderRows` → `updateAmount` перетирает серверный `amount` и у уже сохранённой заявки: список/карточка заказа показывают 0.23, открытая форма — 0.22. Хранимые суммы, итог заказа, доска и печать согласованы.
   Исправление: целочисленная арифметика — цена в копейках и количество в тысячных разбором строки (не через `Number`), `cents = floor((pc × qm + 500) / 1000)` (BigInt либо проверка на 2^53). Добавить случай «половины» в тест.

1. **Деньги — допустимо, кроме MEDIUM-1.** `transfer_items.price numeric(12,2)`, валидатор `priceScale{10,2}` (`validate.go:56`, `salePrice` :293-303): отрицательная → `negative`; 3 знака / > 9999999999.99 / экспонента → `invalid`; 0 допустим. 2. **Итог заказа — допустимо.** Фильтр `direction = 'warehouse_to_client' AND status IN ('in_transit','received') AND kind = 'product'`; единицы и прочие направления не входят (у них `price IS NULL`). Одно выражение `totalAmountSelectSQL` на `Get` и доску; печать берёт `.Card.Task.TotalAmount`. `transfers_amount` только в `GET /tasks/:id` — соответствует спеке (`draft-spec.md:308`).
