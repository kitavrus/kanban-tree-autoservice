# Отчёт: transfers-sales — накладная клиенту

Часть 5 из 6 мастер-спеки `transfers`. Ветка `feat/transfers-sales` (поверх `feat/transfers-partners`), base `4f032b4`, не запушена.

## Что сделано

Документ «склад → клиент» стал накладной: в нём разрешены товарные строки с ценой (`transfer_items.price`, миграция `0016`), у строки есть сумма, у документа — итог. Товар списывается со склада при отправке (движение `client_out`) и возвращается при отмене из «в пути». Итог заказа включает отправленные и полученные накладные; в карточке заказа и печатной форме «Выдача» — строка «Продано по накладным». Исполнитель работает с ценами в накладной так же, как с ценами в заказе. Seed-demo дополнен двумя накладными.

## Ревью

**APPROVED** — high 0 / medium 1 / low 5 (`8-code-review/output.md`). Хранимые суммы, итог заказа, доска и печать считаются одной формулой `Σ round(price × qty_sent, 2)` точной арифметикой — согласованы.

Исправлено после ревью: предпросмотр суммы в форме считался float'ом и при дробном количестве расходился с сервером на копейку (0.15 × 1.5: форма 0.22, сервер 0.23) — переведён на целочисленную арифметику BigInt в копейках (MEDIUM, E2E `TR-021`); предпросмотр при пустой цене считает по цене каталога; тесты округления на «половинках»; реальная проверка неотрицательных остатков в seed-demo.

## Known issues

- **Двойное списание не контролируется:** один товар можно списать и услугой заказа, и накладной — по спеке правило на пользователе (DS-011).
- **Спека описывает суммы строками, код отдаёт JSON-числа** (`price`, `line_total`, `amount`, `transfers_amount`) — as-built проекта; обновить `draft-spec.md`.
- Нечисловая цена в теле (`"abc"`) даёт 400 на разборе без `details.fields`; в UI ловится на клиенте («Некорректная цена»).
- `transfers_amount` есть в `GET /tasks/:id` и ответах мутаций, в элементах списка `GET /tasks` — нет (по спеке).
- Откат миграции `0016` удаляет товарные строки накладных, движения остатка остаются.
- Исполнителю на `/transfers` грузится весь каталог товаров (до 10 000 позиций) — вопрос объёма, не доступа.
- `money()` через `toFixed` теряет копейки на суммах выше ~9·10^13 (as-is для всех сумм проекта).
- E2E по-прежнему оставляет неудаляемые заказы с документами — гонять на пересоздаваемой БД (см. отчёт `transfers-partners`).
- Миграция `0016` не применялась к общей dev-БД (как `0014`, `0015`).
- Спека приведена к as-built 2026-10-08 (ветка feat/transfers-followups).
