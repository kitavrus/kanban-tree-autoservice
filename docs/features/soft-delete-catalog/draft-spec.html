§1. Суть задачи

Удаление записей каталога и типов оборудования становится восстановимым и существует рядом с архивом. Для администратора; исполнитель видит бейджи «удалён» в заказах.

Бизнес (что делает пользователь/процесс):

  1. 1Администратор удаляет товар, услугу, категорию или тип оборудования с причиной — запись исчезает из справочника и уходит в «Удалённые» (§8.1) — DS-014, DS-020.
  2. 2Администратор по-прежнему отправляет запись в архив и возвращает из архива — это отдельное действие (§8.1) — DS-009.
  3. 3Администратор восстанавливает запись — она возвращается в справочник в том же виде: активной либо архивной (§8.2) — DS-009.
  4. 4Любой пользователь в заказе видит бейдж «удалён» у услуги и товара, удалённых из каталога (§8.3) — DS-014.

Логика (правила системы):

  1. 5Удаление и архив независимы: архивная запись видна в справочнике и не предлагается в выборе; удалённая видна только в «Удалённых»; при восстановлении признак архива прежний — DS-009.
  2. 6Ссылки удалению не мешают: отказы PRODUCT_IN_USE, SERVICE_IN_USE, CATEGORY_IN_USE, EQUIPMENT_TYPE_IN_USE сняты; в заказах, составе услуг, единицах оборудования удалённая запись остаётся с бейджем — DS-014.
  3. 7Товар с ненулевым остатком хотя бы на одном складе не удаляется; остаток, появившийся у удалённого товара позже (возврат из заказа, приём документа), виден в отчёте «Остатки» с пометкой «удалён» и может быть списан корректировкой — DS-021, DS-042.
  4. 8Название удалённой категории (в пределах её вида) и удалённого типа свободно; восстановление при занятом названии — отказ — DS-017.
  5. 9Удалённая запись не выбирается в новых заказах, услугах, товарах, единицах оборудования, документах — DS-014.
  6. 10Время: deleted_at — UTC (timestamptz), показ и фильтр — по поясу пользователя, «ДД.ММ.ГГГГ ЧЧ:ММ» — DS-025 (краткий дубль §3).
  7. 11Конкурентный доступ: удаляем запись → один UPDATE с условием «ещё не удалена» (товар — под блокировкой строк остатка); восстанавливаем → условие «удалена», уникальность названия держит частичный индекс; правка действующей записи остаётся last-write-wins — DS-024 (краткий дубль §3).

Техника (API/данные/интеграции):

  1. 12Данные: по три новые колонки в products, services, catalog_categories, equipment_types; два уникальных индекса названий становятся частичными (§4).
  2. 13API: четыре адреса удаления меняют поведение, запрос и ответ, четыре новых адреса восстановления (§6.1–§6.8); новые поля-признаки в ответах, условие «не удалён» в списках и выборе, виды раздела «Удалённые» и служебной уборки (§6.9).
  3. 14Пакеты: internal/features/catalog, internal/features/equipmenttypes, internal/features/board, internal/features/clients, internal/features/transfers, internal/features/softdelete.
  4. 15Внешних систем нет.

UI (графическая часть):

  1. 16Каталог (товары, услуги, категории) и типы оборудования: «Удалить» рядом с «В архив» открывает общее окно с причиной (§8.1).
  2. 17«Удалённые»: новые вкладки «Товары», «Услуги», «Категории», «Типы оборудования» (§8.2).
  3. 18Карточка заказа, формы каталога и оборудования: бейджи «удалён», «категория удалена»; выбор без удалённых (§8.3).

§3. Нефункциональные требования

Конкурентность (по операциям):

  1. 23Удаление товара:
    • 24одна транзакция, порядок блокировок «товар → категория → product_stock» (принятое уточнение реализации: общий порядок с правкой товара, иначе взаимная блокировка с формой товара): строка товара FOR UPDATE (нет либо удалён → 404), строка его категории, затем строки product_stock товара; есть строка с stock <> 0 → 409 PRODUCT_HAS_STOCK; затем UPDATE товара — DS-021, DS-024
    • 25отправка заявки с этим товаром одновременно с удалением товара: отправка ждёт блокировку строки товара и затем видит его удалённым → 409 TRANSFER_HAS_DELETED_REFS; отправка выиграла → товар в пути, остаток источника уменьшен, удаление проверяет остаток как обычно — DS-047
    • 26правка остатков через форму товара блокирует те же строки (as-is updateStocks) и проверяет deleted_at IS NULL товара: удаление выиграло → 404 PRODUCT_NOT_FOUND; правка выиграла → удаление видит остаток и отказывает; ручная корректировка из отчёта «Остатки» удалённый товар не отклоняет (DS-042) — она идёт под той же блокировкой строк остатка, остаток не теряется
  2. 27Удаление услуги, категории, типа оборудования:
    • 28один UPDATE с условием deleted_at IS NULL; 0 строк → 404 своего вида; второй одновременный запрос → 404 — DS-024
  3. 29Восстановление (все четыре вида):
    • 30один UPDATE с условием deleted_at IS NOT NULL; не удалена → 409 NOT_DELETED; у категории и типа нарушение частичного уникального индекса → 409 NAME_TAKEN — DS-017, DS-024

  5. 33Выбор записи одновременно с её удалением (товар в услугу заказа, услуга в заказ, категория в товар, тип в единицу):
