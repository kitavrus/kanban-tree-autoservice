# Отчёт: soft-delete-catalog (часть 5 из 6 мастера soft-delete)

**Дата:** 2026-10-08 · **Ветка:** `feat/soft-delete-catalog` (стопкой на `feat/soft-delete-clients`, база `7074cd1`) · **Коммиты:** `ca6251e`, `074886c` · **Вердикт ревью:** APPROVED

## Что сделано

Товары, услуги, категории и типы оборудования удаляются с возможностью восстановления — рядом с существующим архивом: «В архив» остаётся как было, «Удалить» отправляет запись в раздел «Удалённые» (четыре новые вкладки; у архивных записей пометка «в архиве»). Прежние отказы «используется» сняты: в заказах, услугах и документах удалённые записи остаются видны с пометкой «удалён», в новых выбрать их нельзя. Товар с ненулевым остатком удалить нельзя. Название удалённой записи свободно; при восстановлении, если оно уже занято, — отказ «Название занято». Если на удалённом товаре всё же появился остаток (возврат из заказа, приём документа «в пути»), он виден в отчёте «Остатки» с пометкой «удалён», и его можно только списать. Заявку с удалённым товаром нельзя отправить, восстановить и нельзя отменить проведение её документа. Счётчик единиц у типа оборудования считает только действующие единицы.

Технически: миграция `0022_soft_delete_catalog` (поля удаления в четырёх таблицах, уникальные индексы названий категорий и типов стали частичными), удаление отвечает 200 с телом (было 204), `POST /api/v1/…/restore` для четырёх видов, источники в пакете `softdelete`, служебная уборка, поля `category_is_deleted`, `product_is_deleted`, `service_is_deleted`, `type_is_deleted`, удалённые записи в демо-данных.

## Known issues / отложено

- Отказ отправки заявки с удалённым товаром и правило «остаток удалённого товара только списывается» (код `PRODUCT_DELETED_WRITE_OFF_ONLY`) — решения оркестратора по ревью, вносятся в спеку; пользователь уведомлён.
- Удалённый товар с остатком только на архивном складе: списать можно через API, но отчёт «Остатки» архивные склады не показывает (строка с нулями), а окно корректировки предлагает и склады без остатка (выбор такого склада даёт «Товар не найден») — перенесено в часть 6.
- Уборка тестовых данных в E2E не убирает около 80 записей каталога за прогон (типы оборудования, на которые ссылаются единицы клиентов; товары с журналом склада) — утечка только на одноразовом стенде; раньше происходила молча. Отдельной задачей: убирать клиентов теста до типов и товар вместе с журналом.
- Нестабильный SUP-002 (поставщики) — причина не установлена, с частью 5 не связан; отдельной задачей.
- Low из ревью: удаление категории при ошибке причины теряет фильтры списка; SSR-обработчики ходят в репозиторий мимо сервиса; дубли типов `Actor`/`DeleteResponse` в двух пакетах; откат миграции 0022 упадёт, если есть одноимённые удалённая и действующая записи (режим MVP); отдельных E2E на отказ отправки и на отказ увеличения остатка нет (покрыты Go-тестами).
