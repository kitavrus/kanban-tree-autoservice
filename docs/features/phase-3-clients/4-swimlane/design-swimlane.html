Swimlane: Клиенты и оборудование

Фаза 3 — управление клиентами, телефонами, типами оборудования и реестром единиц

Цели: CRUD для клиентов с телефонами и оборудованием; каталог типов оборудования с архивированием; разделение прав (администратор/исполнитель); оптимистичная блокировка редактирования клиентов.

Ключевые потоки данных

AC-001: Создание клиента
POST /api/v1/clients (Admin) → 201 ClientResponse
Request payload:
  • company_name (required, trim+notblank)
  • address, contact_name, contact_position (optional)
  • phones: [{phone, note}, …] ≥1 phone (required)
Response fields:
  • id, company_name, address, contact_name, contact_position
  • phones: [{phone, note}]
  • equipment_count, version, created_at, updated_at
AC-005: Редактирование клиента (конфликт версий)
PUT /api/v1/clients/:id (Admin) → 200 | 409 CLIENT_VERSION_CONFLICT | 404
Request:
  • version (required, int64) — проверка оптимистичной блокировки
  • Прочие поля как в Create (для SSR скрытый version в форме)
На конфликт (409):
  • SSR: форма перерисовывается с введёнными значениями + сообщение
  • Кнопка «Открыть актуальную версию» → GET /clients/:id
AC-008/AC-009: Создание и правка оборудования
POST /clients/:id/equipment (Admin+Executor) → 201 EquipmentResponse
Request payload:
  • type_id (required, UUID, проверка is_active)
  • brand, model (required), sku, serial (optional strings)
  • specs: [{k, v}] — заполняются из шаблона type_id, редактируются
  • note (optional)
ADR-002: Шаблон spec_keys
  • <option data-spec-keys='["key1","key2"]'> — JSON атрибут
  • Смена типа: заполненные specs сохраняются, пустые замещаются шаблоном
  • row-list.js — контроль добавления/удаления строк specs
AC-012: Удаление типа оборудования (409 IN_USE)
DELETE /api/v1/equipment-types/:id (Admin) → 204 | 409 EQUIPMENT_TYPE_IN_USE
На 409 (тип используется):
  • SSR: форма типа перерисовывается с ошибкой
  • Кнопка «В архив» вместо Delete (POST /catalog/equipment-types/:id/archive)
  • Фильтр «Показать архивные» действует только для Admin (ADR-004)
AC-004: Поиск клиентов
GET /api/v1/clients?q=…&limit=&offset= → ClientListResponse (200)
ADR-003: Нормализация и поиск
  • Поиск по company_name, contact_name ILIKE %q%
  • Поиск по телефонам: ILIKE %q% + regexp_replace для цифр
  • EXISTS (SELECT…) — единая строка клиента, честный total
AC-006: Удаление клиента
DELETE /api/v1/clients/:id (Admin) → 204 | 404
SSR: POST /clients/:id/delete (ADR-103)
  • Confirm-диалог: «Удалить клиента «{company}»? Вместе с ним будет удалено N единиц»
  • form[data-confirm] + KT.uiConfirm + обработчик
  • Каскадное удаление: телефоны и оборудование (ON DELETE CASCADE)
AC-013: Разделение прав (Executor vs Admin)
SSR меню: Executor не видит «Клиенты» и «Каталог»
Executor может:
  • GET /api/v1/clients (получить данные для выпадающей в заказе)
  • POST /api/v1/clients/:id/equipment (завести оборудование)
  • GET /api/v1/equipment-types?include_archived=false (только активные)
  • include_archived=true молча игнорируется (whitelist-откат, не 403)
Ошибки валидации и состояния
Sentinel-коды из design-errors.md
Основные коды:
  • CLIENT_VERSION_CONFLICT (409) — оптимистичная блокировка
  • EQUIPMENT_TYPE_IN_USE (409) — каскад FK RESTRICT
  • EQUIPMENT_TYPE_NAME_TAKEN (409) — имя занято активным типом
  • EQUIPMENT_TYPE_NAME_ARCHIVED (409) — имя занято архивным типом (вернуть из архива)
  • Валидация (400) — поля required/format, type_id битый/в архиве
  • IDOR (404) — несуществующий id или чужой ресурс
