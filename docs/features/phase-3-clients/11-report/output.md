# Отчёт: phase-3-clients — клиенты, телефоны, оборудование, типы оборудования

**Трек:** /pipeline (обычный, draft-spec нет) · **Tier:** M · **CM-1:** MVP · **UI-scope:** swagger:no / adaptive:min / themes:both · **Ветка:** `feat/phase-3-clients` (база `d3de17e`)

## 1. Итог

В фазе 3 реализованы клиенты с несколькими телефонами, оборудование клиента с характеристиками по шаблону типа и справочник типов оборудования с архивом. Бэкенд на Go и SSR-интерфейс (html/template + vanilla JS, без Vue по D30) покрыты unit-, live-integration- и E2E-тестами. Code Review и mobile-api review завершились вердиктом **APPROVED** (0 HIGH / 0 MEDIUM), QA — **APPROVED** (0 находок). Полная E2E-сюита прошла 57/57 в двух полных прогонах. Фича готова к PR.

## 2. Что сделано по стадиям

- **Research** — зафиксированы текущие паттерны (users/auth, SSR, testutil) и DB-baseline; один fix-loop artifact_lint (file:line и размер).
- **Spec Interview** — два батча вопросов, PRD с AC-001…AC-014 одобрен на PRD-review; Tech Spec закрепил отступления В-1 и В-5.
- **Design** — ADR (в т.ч. ADR-003 поиск по телефону, ADR-004 include_archived, ADR-006 меню), контракт, SQL, слои, ошибки, тест-матрица. Один цикл design-review: по HIGH mobile-ревьюера введён отдельный код `EQUIPMENT_TYPE_NAME_ARCHIVED` (имя занято архивным типом), чтобы не путать его с `EQUIPMENT_TYPE_NAME_TAKEN`.
- **Swimlane** — интерактивная диаграмма роль×фаза; после fix-loop не перерисовывалась, потому что потоки не менялись.
- **Plan** — 9 фаз с чередованием backend/frontend (SSR).
- **Executing** — все 9 фаз закрыты. В фазе 08 был fix-loop по EQ-004: спецификация шаблона характеристик ожидала 2 строки, а рендерилось 3; исправлено за одну итерацию.
- **Code Review** — два fix-loop'а. Первый: NUL-байт и невалидный UTF-8 теперь дают 400 `invalid_text` вместо 500, исправлены индексы ошибок строк формы, поиск телефона приведён к ADR-003, 23503 разбирается по имени constraint, введены PRG-редиректы с flash. Второй: исправлена регрессия частичного ввода телефона (поиск по сырым цифрам ИЛИ без ведущей 7/8). Итог — APPROVED.
- **Validation** — 57/57 в двух полных прогонах (сводный гейт Executing и Validation), watch-gate пройден, пользователь подтвердил переход к QA.
- **QA** — 10 классов проверок на живом API и SSR, три evidence-файла, APPROVED.

## 3. Ключевые решения по ходу

- **Отступление от D30 (Tech Spec В-1, утверждено пользователем):** фича написана вручную двумя плоскими пакетами (`clients`, `equipmenttypes`), а не через z-scaffold.
- **D26 «есть заказы → 409» целиком перенесено в фазу 5 (В-5):** проверки на заказы при удалении клиента или единицы оборудования и их тесты появятся вместе с заказами.
- **Страницы вместо модалок:** формы клиента, оборудования и типа сделаны отдельными SSR-страницами с PRG-редиректами.
- **D28 — оптимистическая блокировка только у клиента:** `version` есть только у клиента (конфликт проверяется в CL-020/LV-020 в двух контекстах). Оборудование и типы работают по last-write-wins.

## 6. Known issues и перенесённое

- **LOW (ревью), MVP-компромиссы:**
  - SSR-список ограничен 200 записями (`maxLimit`) без пагинации; блок оборудования в карточке обрезается на 200.
  - `equipmenttypes/handler.go:67`: ранний return при проверке `is_active`, из-за которого остальные ошибки полей не возвращаются вместе. QA подтвердил это живьём.
  - `equipmenttypes/ssr.go` update: гонка read-then-write по `IsActive` — параллельная архивация может быть откатана (LWW).
- **Закрыто после отчёта ревью:** LOW `digitsAlt` без порога `minSearchDigits` исправлен в 1ee8a4d, QA подтвердил. Текст `8-code-review/output.md` в этой части устарел.
- **Mobile LOW:** для `/equipment-types` нет conditional GET (ETag); мусор в `limit`/`include_archived` молча откатывается на дефолт — это соответствует дизайну.
- **Перенесено в фазу 5:** проверки D26 («есть заказы / было в заказе → 409») и их тесты.
- **Инфраструктура:** на машине остались безымянные dockertest-контейнеры redis/postgres. Я их не удалял, потому что они могли принадлежать другим сессиям. Похоже на неполный teardown dockertest — стоит проверить `pkg/testutil`.
- **Observability** (Monitoring & Alerting Spec) отложена (MVP, прода нет); спаны не проверялись. Live-проверки mobile API на стенде не было, потому что dev-стенд не задеплоен.
