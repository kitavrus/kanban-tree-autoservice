# Spec decisions: phase-3-clients

> Нормативный журнал решений spec-interview (relay-loop). Закрытые решения плана — `(source: D-NN)` из docs/plan.md §7, не переспрашиваются.
> **Tier:** M | **Совместимость:** MVP (CM-1) | **UI-scope:** swagger:no / adaptive:min / themes:both

## Принято без вопросов (source: план/прототип)
- Поля клиента: компания*, адрес, представитель ФИО, должность, телефоны (номер + примечание) (source: plan §3, prototype openClient)
- Поля оборудования: тип*, производитель, модель*, артикул, SN/VIN, характеристики [{k,v}] по шаблону типа, примечание (source: plan §3, prototype openEquipment)
- Тип оборудования: название*, шаблон характеристик spec_keys, is_active (source: plan §3, D24)
- version у клиентов, 409 при конфликте; у оборудования/типов version нет (source: D28)
- Удаление: клиент с заказами 409; оборудование — только если не было в заказах; тип используемый — 409 + архив (source: D26)
- Справочники — admin; исполнитель создаёт новое оборудование (source: D19, plan §2)
- Все select — с поиском (source: D6); UI — Bootstrap (source: D38); справочники — z-scaffold (source: D30)

## Батч 1 (Фаза 1, PRD) — закрыт
- **В-1** контекст/метрики/non-goals → принято (Рекомендую): пользователь — admin-приёмщик; метрики: клиент+1 тел+1 ед. ≤2 мин; 100% демо-клиентов seed-demo в реестре к фазе 5; 0 молчаливых потерь правок (409). Non-goals: история/число заказов (ф.5/6), импорт/дедуп, печать, поиск оборудования на доске.
- **В-2** права executor → (а): чтение clients/equipment/активных типов через API + `POST /clients/:id/equipment`; прочие мутации → 403; SSR «Клиенты»/«Каталог» — admin-only.
- **В-3** удаление/архив → (а)–(г): (а) проверки «есть заказы»/«было в заказе» — точка расширения, сейчас всегда проходят, реальная — фаза 5; (б) DELETE клиента без заказов каскадно удаляет телефоны+оборудование, confirm с числом единиц; (в) кнопка «Удалить» у оборудования + confirm; (г) тип: не используется → DELETE, используется → 409 «в архив»; архивный скрыт из выбора новых, виден у существующих; фильтр «показать архивные» + восстановление.
- **В-4** UX → (а)–(ж): (а) ≥1 телефон, пустые строки отбрасываются, лимит длины примечания; (б) 409 version → форма с введёнными значениями + сообщение + «Открыть актуальную версию»; (в) поиск `?q=` компания/представитель/телефон, сортировка по компании, колонки без «Заказов»; (г) страницы `/clients`, `/clients/new`, `/clients/:id`, `/clients/:id/equipment/new`, `/equipment/:id` (PRG, без вложенных модалок); (д) `/catalog/equipment-types`, меню «Каталог» туда; имя типа уникально case/trim-insensitive → 409; (е) шаблон — только при создании/смене типа, заполненные сохраняются, существующие не меняются, свободные ключи разрешены; (ж) без уникальности компании и SN/VIN.
- **PRD Review** → approved (2026-09-25), AC-001…AC-014.

## Батч 2 (Фаза 2, Tech Spec) — закрыт
- **В-1** → вручную, 2 плоских пакета `internal/features/clients` (clients+phones+equipment) и `internal/features/equipmenttypes`, по образцу users; z-scaffold не используется — осознанное отклонение от D30 для фазы 3 (7 расхождений research), D30 в силе для фазы 4.
- **В-2** → лимиты приняты: company 1–200, address ≤500, contact_name/position ≤200; phones 1–20, phone ≤32 + ≥1 цифра, note ≤200; brand/sku/serial ≤200, model 1–200, note ≤1000, specs ≤50, k ≤100, v ≤500, v без k → ошибка, дубли k разрешены; type name 1–100, spec_keys ≤50×≤100, пустые/дубли (case-insens.) отбрасываются молча; trim везде, длина в символах, 400 с fields.
- **В-3** → phones replace-all в одной транзакции с проверкой+инкрементом version; version — поле body (API) / hidden (SSR); mismatch → 409 `CLIENT_VERSION_CONFLICT`; equipment/types без version (LWW, D28); правка оборудования не трогает version клиента; DELETE клиента version не проверяет.
- **В-4** → (а)–(е): URL по plan §4 + `?include_archived=true`, архив через PUT `is_active`; коды `CLIENT_VERSION_CONFLICT`/`EQUIPMENT_TYPE_NAME_TAKEN`/`EQUIPMENT_TYPE_IN_USE` 409, 404; архивный тип на новой ед./смене типа → 400 поле type_id, без смены — ок; FK clients→phones/equipment CASCADE, equipment.type_id RESTRICT; список `{items,total,limit,offset}` limit 50, счётчик единиц без N+1; двойной submit — disable кнопки + PRG, без серверного дедупа, повторный DELETE → 404.
- **В-5** → (б) «Всё в фазу 5»: проверки D26 «клиент с заказами»/«оборудование было в заказе» целиком (код, заглушка, коды `CLIENT_HAS_ORDERS`/`EQUIPMENT_IN_ORDERS`, тесты) — в фазе 5; в фазе 3 DELETE клиента/оборудования безусловный. Наблюдаемость — не оспорена → штатная (OTel/slog/Prometheus), алерты deferred до прода (CM-1 MVP). ⚠ трактовка «(б)» = альтернатива вопроса В-5 (не подпункт) — отмечено оркестратору для подтверждения.
