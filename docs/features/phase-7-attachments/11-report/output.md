# Фаза 7 — вложения заказа: отчёт

**Итог:** в карточке заказа можно прикладывать фото, видео и PDF. Ревью — **APPROVED** со второго захода. Первый заход нашёл уязвимость: запрос на загрузку, отклонённый без авторизации, позволял протащить в соединение второй запрос (HTTP request desync). Она закрыта и покрыта тестом. Полная E2E-сюита — 123/123.

## Что сделано

В карточке заказа появился раздел «Вложения». Он показывает список файлов с превью: фото открывается целиком, видео играет встроенным плеером, PDF — ссылкой. Файл загружается с блокировкой кнопки на время отправки, удаляется после подтверждения.

**Лимиты (D21):** фото — до 20 МБ, видео — до 500 МБ, PDF — до 20 МБ. При превышении пользователь видит понятную ошибку с указанием лимита.

**Хранение.** Файлы лежат на диске через интерфейс `FileStore` (`internal/filestore`, локальная реализация). Каталог задаётся переменной `UPLOADS_DIR`, по умолчанию `./uploads` — он в `.gitignore`. Позже хранилище можно заменить на MinIO/S3 без переписывания фичи. Метаданные — в таблице `task_attachments` (миграция `0007`).

**Безопасность:**
- **Тип файла.** Определяется по содержимому, а не по расширению: поддерживаются JPEG/PNG/GIF/WebP, MP4/WebM/MOV, PDF. HTML, SVG и архивы не проходят.
- **Имя на диске** — uuid; из исходного имени вырезаются управляющие и bidi-символы.
- **Отдача файла:** тип берётся из БД, выставляются `nosniff`, `Content-Disposition` с безопасным именем и приватный кэш. Для перемотки видео поддержаны Range-запросы.
- **Права:** смотреть и загружать может любой сотрудник, удалять — автор или администратор.
- **Удаление заказа** удаляет его вложения. Файлы стираются после фиксации транзакции.

**Приём запроса:** тело читается потоком, файл пишется сразу на диск. Для всех остальных роутов сохранён прежний лимит 4 МБ.

**Попутно исправлен общий компонент `ui-dialog.js`.** Диалоги теперь показываются по очереди, и в DOM одновременно находится не больше одного. Раньше при быстром «Отмена → снова Удалить» на экране на мгновение оказывалось два диалога и два затемнения фона.

Решения исполнителя D-701…D-720 записаны в `0-setup/light-progress.md`.

## Известное

- Нет сборщика «осиротевших» файлов: файл на диске без строки в БД после аварийного падения процесса.
- Для прода за nginx нужен `client_max_body_size 501m` на роуте загрузки. Настройки nginx в этом репозитории нет.
- Обработчик вложений импортирует `internal/server/middleware` ради одной ошибки (LOW ревью). Её лучше перенести в `pkg/errorspkg`.
