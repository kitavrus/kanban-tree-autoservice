§1. Суть задачи

Справочник поставщиков для будущих документов «поставщик → склад». Для администратора.

Бизнес (что делает пользователь/процесс):

  1. 1Администратор заводит поставщика: название, контактное лицо, телефон, адрес, примечание (§8.1) — DS-007.
  2. 2Отправляет поставщика в архив и возвращает из архива; удаления нет (§8.1) — DS-007.

Логика (правила системы):

  1. 3Название обязательно и уникально без учёта регистра, включая архивные — DS-007.
  2. 4Время: created_at, updated_at хранятся в UTC (timestamptz); на экране справочника даты не показываются — DS-031 (контекст, реализуется в user-timezone).
  3. 5Конкурентный доступ: правка поставщика → last-write-wins, версии нет (как warehouses); создание с тем же названием → второй запрос получает 400 name: duplicate (уникальный индекс) — DS-043.

Техника (API/данные/интеграции):

  1. 6Таблица suppliers (§4.1), своя миграция.
  2. 7API /api/v1/suppliers: список, создание, правка (§6.1–§6.3).
  3. 8Новый пакет internal/features/suppliers; внешних систем нет.

UI (графическая часть):

  1. 9Пункт меню «Справочники → Поставщики» (/suppliers), только администратор: таблица, поиск, toggle архивных, форма (§8.1).

Out-of-scope:

  1. 10Использование поставщика в документах перемещения (supplier_id, запрет архивного в новом документе) — часть 4 transfers-partners.
  2. 11Удаление поставщика — нет, только архив (DS-007).
  3. 12Закупочные цены, договоры, реквизиты — не ведём (DS-016 — контекст, реализуется в transfers-partners).
  4. 13Демо-поставщики в seed-demo — добавляются в части transfers-partners вместе с документами от поставщика.

§2. Интеграции и master-data

Не применимо: внешних систем нет; suppliers сам является справочником, источник правды — эта фича, ведёт администратор (DS-007).

§5. Статусная модель

Не применимо: статусов нет. Единственный признак состояния — is_active (true — действующий, false — в архиве), переключается в обе стороны администратором через PUT /api/v1/suppliers/:id без ограничений (DS-007, DS-043).

§6. API

Режим B «API + фронтенд». Базовый URL стенда: http://localhost:8080. Авторизация — сессионная cookie sid (плейсхолдер <SID>). Копируй curl в терминал или в Postman: Import → Raw text. Тело ошибки — формат pkg/errorspkg: {code, message, details}; при 400 — details.fields[] с name и message. Ключи — snake_case, URL — kebab-case (CLAUDE.md §API-1).
