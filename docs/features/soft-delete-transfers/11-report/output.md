**Дата:** 2026-10-08 · **Ветка:** `feat/soft-delete-transfers` (стопкой на `feat/soft-delete-core`, база `ecc023b`) · **Коммиты:** `7dcd8bc`, `562e3a3`, `c9b2350` · **Вердикт ревью:** APPROVED

## Что сделано

Документ перемещения удаляется с возможностью восстановления: администратор удаляет заявку или отменённый документ с обязательной причиной, документ уходит во вкладку «Перемещения» раздела «Удалённые» и возвращается кнопкой «Восстановить». Заказ теперь удаляется с любыми документами — отказ `TASK_HAS_TRANSFERS` снят; остатки и местоположение оборудования при этом не меняются. Документы удалённого заказа остаются в «Перемещениях» с пометкой «заказ удалён», их можно довести до конца (принять, откатить, отменить, отправить, править), создать новый документ по удалённому заказу нельзя (`TASK_DELETED`). Удалённые документы не мешают сменить клиента заказа; восстановить документ после смены клиента нельзя (`TRANSFER_CLIENT_MISMATCH`).

Технически: миграция `0019_soft_delete_transfers` (три колонки в `transfers`, CHECK — удалённым может быть только документ в «Заявка» или «Отменён»), `DELETE /api/v1/transfers/:id` с телом `{reason, version}`, `POST /api/v1/transfers/:id/restore`, источник вида `transfers` в пакете `softdelete`, служебная уборка вида `transfers`, условие «документ не удалён» во всех чтениях.
