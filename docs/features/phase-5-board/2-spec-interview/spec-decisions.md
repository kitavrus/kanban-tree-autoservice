## Батч 1 (Фаза 1 — PRD + границы фазы) — закрыт

### SD-001 (В-1): Объём схемы услуг/товаров заказа
**Решение: a.** Миграция фазы 5 создаёт схему целиком: `columns`, `tasks`, `subtasks`, `subtask_products`,
`task_stock`, `task_equipment` + FK `stock_movements.task_id → tasks`. UI правки услуг/товаров заказа в фазе 5
нет (D25) — данные только из `seed-demo`. На них реально работают D11/D22 (409 `SUBTASKS_NOT_DONE`),
D17/D34 (списание/возврат), фильтры «вид работ»/«исполнитель услуги» (D19), прогноз «Остатков» (D18),
D26 «оборудование было в заказе → 409». Редактирование услуг/товаров — фаза 6.

### SD-002 (В-2): Тип PK `tasks`
**Решение: a.** `tasks.id BIGSERIAL` (D37). `stock_movements.task_id` альтерится `uuid → bigint` новой миграцией
(безопасно: все существующие записи `manual`, `task_id IS NULL`) + FK.

### SD-003 (В-3): `make seed-demo`
**Решение: a.** Грузит демо-данные прототипа (клиенты, оборудование, каталог с остатками, заказы по всем
колонкам D32 с услугами в разных статусах, товары заказов, произведённые списания) ТОЛЬКО если в БД нет
заказов; иначе — сообщение и выход без изменений. Админа не трогает (D36).

### SD-004 (В-4): Рамка PRD
**Решение: принято как предложено.** Боль — заказы вне системы, не видно этап/списанное/дефицит; JTBD —
согласованный заказ перетаскивается в «В работе», товары списываются сами; метрики — 100% активных заказов
на доске за 2 недели, 0 расхождений остаток vs журнал, перенос p95 < 500 мс; non-goals — полная карточка
(фаза 6), журнал/вложения/комментарии, уведомления, печать/отчёты.

**PRD Review:** одобрен пользователем 2026-09-26 (AC-006 admin-only подтверждён В-5).

## Батч 2 (Фаза 2 — Tech Spec) — закрыт

### SD-005 (В-5): Управление колонками
**Решение: a.** Только admin. «+ Колонка» в actions доски, меню заголовка колонки «Изменить/Удалить»;
порядок — поле «позиция» в форме, без drag&drop колонок. Executor: UI не видит, API записи → 403.

### SD-006 (В-6): Version при переносе
**Решение: a.** `POST /tasks/:id/move` без `version`, last-write-wins по колонке/позиции; move инкрементирует
`version` (открытая форма получит 409 при сохранении). Параллельные move одного заказа сериализуются
`SELECT … FOR UPDATE` строки `tasks` + D34 по товарам. 409 `SUBTASKS_NOT_DONE` → карточка откатывается.

### SD-007 (В-7): Удаление заказа и журнал склада
**Решение: a.** Физический DELETE: сначала возврат товаров (`task_return` c `task_id`), затем удаление;
FK `stock_movements.task_id → tasks(id) ON DELETE SET NULL` — журнал сохраняется без связи.

### SD-008 (В-8): Отметка оплаты
**Решение: a.** Чекбокс «Оплачен» в простой форме, виден/принимается только от admin; `paid_at` ставит/сбрасывает
сервер; на карточке бейдж. Executor, приславший `is_paid` с изменением → 403.
