§1. Суть задачи

Документ «Перемещение» становится единой сущностью для движения товаров и оборудования клиентов между складами, клиентами и поставщиками; каждое движение отслеживается по статусам. Для администратора и исполнителя сервисного центра.

Бизнес (что делает пользователь/процесс):

  1. 1Принимает оборудование клиента в ремонт документом «клиент → склад», всегда по заказу (§5, §8.1) — DS-002, DS-012.
  2. 2Возвращает оборудование клиенту документом «склад → клиент» и тем же документом продаёт дополнительный товар по цене (накладная) — DS-004, DS-011.
  3. 3Перевозит между складами товары и оборудование клиентов документом «склад → склад» — DS-004.
  4. 4Заказывает товары у поставщика документом «поставщик → склад» и принимает по факту — DS-002, DS-015.
  5. 5Ведёт справочник поставщиков (§8.2) — DS-007.
  6. 6Исправляет ошибочно проведённый документ действием «Отменить проведение» — DS-017.
  7. 7В карточке заказа видит местоположение каждой единицы, ссылки на документы и сумму накладных в итоге заказа (§8.3) — DS-003, DS-014.

Логика (правила системы):

  1. 8Один документ, четыре направления, смешанные строки: товар (количество) и единица оборудования клиента — DS-001, DS-010.
  2. 9Состав строк по направлениям — DS-004, DS-010:
    • 10«клиент → склад»: только единицы оборудования этого заказа;
    • 11«склад → клиент»: единицы оборудования этого заказа + товары с ценой;
    • 12«склад → склад»: единицы оборудования любых клиентов + товары;
    • 13«поставщик → склад»: только товары, без цен.
  3. 14«Наше оборудование» — товар каталога с количеством; поштучных единиц без клиента нет — DS-005, DS-009.
  4. 15Статусы одинаковы для всех направлений: «Заявка» → «В пути» → «Получено»; «Отменён» из «Заявки» и «В пути»; «Отменить проведение» возвращает «Получено» в «В пути» (§5) — DS-013, DS-017.
  5. 16Местоположение — одно на единицу оборудования: «у клиента» / «на складе X» / «в пути (документ #N)» — DS-008.
  6. 17Единица оборудования — только в одном незавершённом документе — DS-019.
  7. 18Сумма накладной входит в итог заказа, пока документ «В пути» или «Получено» — DS-014.
  8. 19Время: хранение UTC (timestamptz); показ — по часовому поясу из настройки пользователя на всех экранах системы (краткий дубль §3) — DS-031, DS-032.
  9. 20Конкурентный доступ (краткий дубль §3):
    • 21правка и переходы документа → optimistic lock version + 409;
    • 22остатки товара → FOR UPDATE строк product_stock в порядке (product_id, warehouse_id);
    • 23занятие единицы документом → guard-UPDATE active_transfer_id;
    • 24as-built (D75): строки equipment — FOR NO KEY UPDATE; заказ — FOR KEY SHARE при создании/правке документа с клиентом; порядок: документ → заказ → product_stock → equipment;
    • 25справочник поставщиков → last-write-wins.

Техника (API/данные/интеграции):

  1. 26Таблицы: transfers и transfer_items (переименование и расширение stock_transfers / stock_transfer_items), новая suppliers; ALTER equipment, users, stock_movements, task_equipment; удаляется task_equipment_movements — DS-029, DS-030.
  2. 27API: /api/v1/transfers (9 endpoints), /api/v1/suppliers (3), PUT /api/v1/users/me/timezone; изменения GET /api/v1/tasks/:id/card, GET /api/v1/tasks, DELETE /api/v1/tasks/:id; удаляются три endpoint'а перемещения оборудования в заказе (§6.15).
  3. 28Пакет internal/features/transfers (переименование internal/features/stocktransfers), новый пакет internal/features/suppliers.
  4. 29Внешних систем нет.

UI (графическая часть):

  1. 30«Работа → Перемещения» (/transfers): список с фильтрами + документ (master-detail) — виден и исполнителю, но только документы с клиентом (§8.1).
  2. 31«Справочники → Поставщики» (/suppliers): список + форма, только администратор (§8.2).
  3. 32Карточка заказа: у оборудования — местоположение и ссылка на документ вместо кнопок «Отправить / Принять / Отменить отправку»; блок «Перемещения заказа» с кнопками «Принять от клиента» и «Вернуть клиенту»; строка «Продано по накладным» в итогах (§8.3).
  4. 33Настройка часового пояса пользователя (§8.4); все экраны системы показывают дату и время по ней (DS-032).

Out-of-scope:

  1. 34Мягкое удаление с восстановлением и отчёт «Удалённые заказы» — отдельная следующая задача (DS-022); до неё действуют запреты удаления DS-025, DS-026.
  2. 35Статус товара заказа «ждёт поставку» и заказ у поставщика под заказ клиента — отдельная задача после перемещений; связь документа «поставщик → склад» со строками товаров заказа не закладывается (DS-024).
  3. 36Закупочные цены и сумма документа от поставщика — не ведём (DS-016).
  4. 37Создание нового товара каталога из документа — товар сначала заводится в «Каталоге» (DS-016).
  5. 38Возврат проданного товара от клиента — нет: от клиента принимается только его оборудование (DS-004).
  6. 39Поштучный учёт собственного оборудования с серийными номерами — нет (DS-009).
  7. 40Отдельная отметка оплаты накладной — нет: отметка «Оплачен» у заказа одна (DS-014).

§3. Нефункциональные требования

Конкурентность (К-3 — по операциям):

  1. 48Правка и переходы документа (PUT, send, receive, cancel, unreceive, DELETE):
    • 49optimistic lock: обязательный version в теле; строка transfers берётся FOR UPDATE — DS-048
    • 50устаревшая версия → 409 TRANSFER_VERSION_CONFLICT; версия сверяется ДО статуса; недопустимый переход → 409 TRANSFER_STATUS_CONFLICT — DS-048
  2. 51Остатки товара (send, receive, cancel, unreceive):
    • 52Lock Order: transfers FOR UPDATE → строки product_stock FOR UPDATE в порядке (product_id, warehouse_id) — as-is D50, DS-048
    • 53отправка в минус разрешена, ответ несёт warnings — DS-023
  3. 54Занятие единицы оборудования документом:
    • 55guard-UPDATE UPDATE equipment SET active_transfer_id = :id WHERE id = :eq AND active_transfer_id IS NULL; 0 строк → 409 EQUIPMENT_IN_TRANSFER с номером мешающего документа — DS-019, DS-041
    • 56Lock Order: после product_stock — строки equipment FOR NO KEY UPDATE в порядке id
    • 57as-built (D75): FOR NO KEY UPDATE, а не FOR UPDATE — вставка строки документа держит на единице FOR KEY SHARE, иначе параллельные создания взаимно блокируются; заказ блокируется FOR KEY SHARE при создании/правке документа с клиентом; порядок блокировок: документ → заказ → product_stock (по product_id) → equipment (по id); при удалении заказа его документы НЕ блокируются (блокируется только заказ; страховка — FK transfers.task_id RESTRICT), отменённые документы удаляет board SQL-запросом в транзакции удаления
  4. 58Смена местоположения единицы (send, receive, cancel, unreceive):
    • 59guard по фактическому местоположению под блокировкой строки equipment; не совпало → 409 TRANSFER_EQUIPMENT_NOT_AT_SOURCE — DS-036
  5. 60Итог заказа: не хранится, считается запросом при чтении — расхождения невозможны — DS-014
  6. 61Справочник поставщиков: last-write-wins, версии нет (как warehouses) — DS-043
  7. 62Часовой пояс пользователя: last-write-wins — DS-031
    • 63as-built (D82): смена своего пояса обновляет users.updated_at; version не проверяется и не увеличивается

§6. API

Режим B «API + фронтенд». Базовый URL стенда: http://localhost:8080. Авторизация — сессионная cookie sid (плейсхолдер <SID>). Копируй curl в терминал или в Postman: Import → Raw text. Тело ошибки — формат pkg/errorspkg: {code, message, details}; при 400 — details.fields[] с name и message. Все ключи — snake_case, URL — kebab-case (CLAUDE.md §API-1). as-built (D76, D80): количества и деньги (qty_sent, qty_received, price, line_total, amount, transfers_amount, total_amount, warnings[].stock, warnings[].min_stock) — JSON-числа в запросе и в ответе, не строки. Текстовые поля с недопустимыми символами (например NUL в note, reason, полях поставщика) → 400 invalid_text. Текст отказа в доступе единый — «Нет доступа» (страница отказа и собственные 403 API перемещений); admin only — технический текст middleware admin-only API. Документ чужого направления для исполнителя → 404; unreceive и DELETE документа для исполнителя → 403 всегда (роль проверяется первой, в т.ч. для несуществующего документа).
