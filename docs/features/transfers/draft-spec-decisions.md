# Draft-spec decisions: Перемещения (transfers)

## Батч 0 (2026-10-07) — решения пользователя до интервью (переданы оркестратором)
- **В-0.1:** Один документ или две сущности (товары / оборудование)? → **Ответ:** один документ «Перемещение» со смешанными строками: товары (qty) + единицы оборудования; расширяем существующее перемещение (`stock_transfers`: #N bigserial, version, статусы requested/in_transit/received/cancelled), вторую сущность не заводим → DS-001
- **В-0.2:** Как участвует контрагент? → **Ответ:** контрагент — точка маршрута. Направления: клиент → склад (приём в ремонт), склад → склад, склад → клиент (возврат); дословно «1, но еще есть заказ товаров от поставщиков» → плюс поставщик → склад → DS-002
- **В-0.3:** Кнопки «Отправить / Принять / Отменить отправку» у оборудования в карточке заказа (D57)? → **Ответ:** убрать; оборудование перемещается только через документ, в карточке — местоположение и ссылка на документ → DS-003
- **В-0.4:** Состав строк по направлениям? → **Ответ (дословно):** «принять мы можем только то что прислал нам клиента, отправить мы уже можем то что нам прислал клиент + дополнительное оборудование или товар, транспортировать между складами мы можем и оборудование наше и клиента и товары. от поставщика оборудование и товары» → DS-004

## Батч 1 (2026-10-07) — модель данных
- **В-1:** Что такое «наше оборудование» в учёте (поштучно в справочнике оборудования без клиента / количеством как товар / оба вида)? → **Ответ (дословно, вариант не выбран):** «Я же написал пример, что есть товар, который приходит и оборудование на ремонт к нам, и есть то, что мы заказываем о поставщике, то есть наше оборудование, которое мы и комплектующие, которое мы потом продаем клиенту. То есть есть те товары, которые привязаны к клиенту и есть те, которые не привязаны к клиенту. То есть товар, который мы закупили у поставщика, он наш товар, он не принадлежит никакому клиенту, пока мы его не продали ему.» → DS-005 (закрыто: закупленное у поставщика — наше, без клиента, до продажи; у клиента — после продажи). Развилка «поштучно/количеством» НЕ закрыта → переспрошено в батче 2 (В-5).
- **В-2:** Что происходит с «нашим» оборудованием при отправке клиенту? → **Ответ:** a) единица переходит клиенту: становится его оборудованием, у нас больше не числится → DS-006
- **В-3:** Справочник поставщиков? → **Ответ:** a) отдельный справочник «Поставщики»: название (обязательное, уникальное), контактное лицо, телефон, адрес, примечание; только администратор; без удаления — архивирование → DS-007
- **В-4:** Где живёт местоположение оборудования? → **Ответ:** a) на самой единице оборудования: «у клиента» / «на складе X» / «в пути (документ #N)»; карточка заказа только показывает; новая единица клиента по умолчанию «у клиента» → DS-008

## Батч 2 (2026-10-07) — флоу направлений
- **В-5:** Пример «3 принтера + 10 картриджей от поставщика»: поштучные карточки оборудования или количество? → **Ответ:** b) всё количеством — и принтеры, и картриджи товары каталога (+3 и +10), без серийников; карточка оборудования клиента появляется только когда клиент принесёт принтер в ремонт (заводится руками, как сейчас) → DS-009
  - Следствие (inferred): «наше оборудование» = товар каталога с количеством; поштучных единиц без клиента нет, `equipment.client_id` остаётся NOT NULL → **DS-005 уточнён** (формулировка: «закупленное у поставщика — товар каталога, наш, без клиента, до продажи»).
  - Следствие (inferred): единицы оборудования без клиента не существует → **DS-006 superseded by DS-011** (вместо «единица переходит клиенту» — «товар списывается клиенту по цене продажи»).
  - Следствие (inferred): строки-единицы оборудования — только оборудование клиентов; в документе «поставщик → склад» — только товарные строки → DS-010
- **В-6:** Связь документов «клиент → склад» / «склад → клиент» с заказом? → **Ответ:** b) ссылка на заказ обязательна: без заказа оборудование от клиента не принять и клиенту не вернуть → DS-012
- **В-7:** Что делает документ «склад → клиент» с дополнительным товаром? → **Ответ:** b) в строках документа есть цена продажи и итоговая сумма документа (документ = накладная на продажу) → DS-011
- **В-8:** Подтверждение на стороне клиента? → **Ответ:** a) те же три шага (Заявка → В пути → Получено) для всех направлений; «Принять» у «склад → клиент» нажимает наш сотрудник; «клиент → склад» можно создать и принять одним действием → DS-013

## Батч 3 (2026-10-07) — деньги, поставщик, исправление ошибок
- **В-9:** Как сумма накладной «склад → клиент» соотносится с заказом? → **Ответ:** a) входит в итог заказа: блок «Продано по накладным» в карточке, итог = услуги + товары услуг + накладные, отметка «Оплачен» одна; в сумму идут только отправленные/полученные накладные (заявка и отменённая — нет) → DS-014
- **В-10:** Приход от поставщика: расхождение факта с заказанным? → **Ответ:** a) три шага (Заявка = заказали, В пути = отгрузил, Получено = приняли с фактом); недопоставка — закрываем по факту, довоз новым документом; факт больше заказанного разрешён только для прихода от поставщика → DS-015
- **В-11:** Закупочная цена и создание товара в документе от поставщика? → **Ответ:** c) цен нет, только количество; товары только из каталога → DS-016
- **В-12:** Как исправлять ошибочно проведённый документ? → **Ответ:** b) администратор может «Отменить проведение» полученного документа: остатки и местоположение оборудования откатываются, документ возвращается в «В пути»; обязательная причина → DS-017 (пересматривает финальность `received` из D51)

## Батч 4 (2026-10-07) — права, конкурентность, откат, удаления
- **В-13:** Кто работает с документами? → **Ответ:** a) исполнитель создаёт и проводит документы с клиентом («клиент → склад», «склад → клиент», включая товары с ценой) и видит в списке только их; «склад → склад», «поставщик → склад», справочник поставщиков и «Отменить проведение» — только администратор → DS-018
- **В-14:** Когда единица оборудования «занимается» документом? → **Ответ:** a) сразу при добавлении в заявку: единица только в одном незавершённом документе (заявка или в пути), иначе ошибка «уже в перемещении #N»; освобождается при получении или отмене → DS-019
- **В-15:** Края «Отменить проведение» (товар израсходован / единица уехала дальше / заказ оплачен)? → **Ответ (дословно, вариант не выбран):** «Мы можем договориться с клиентами убрать этот заказ, этот товар из этого заказа мы можем поставить статус ждет поставку и заказать этот товар у поставщика и ждать, пока он придет. Мы должны иметь возможность все менять.» → DS-020 (принцип «всё можно менять»: откат не блокируется учётными причинами; детали запретов уточняются В-17) + новый объём «ждёт поставку» (уточняется В-18)
- **В-16:** Удаление и правка, пока документы существуют? → **Ответ (дословно, вариант не выбран):** «У нас должен быть софт делит, то есть мы можем все удалять, но при этом при необходимости мы нажимаем и восстанавливаем удаленное. Можно тогда сделать отдельный отчет, в котором видно удаленные заказы.» → DS-021 (принцип: soft delete с восстановлением + отчёт «Удалённые заказы»; охват и место реализации уточняются В-19/В-20). As-is: заказ удаляется физически (hard delete, решение фазы 5).
- **В-16 (уточнение, передано оркестратором):** Soft delete — в рамках `transfers` или отдельно? → **Ответ (дословно):** «мягкое удаление делаем отдельной задачей» → DS-022 (closed: soft delete с восстановлением и отчёт «Удалённые заказы» — ВНЕ объёма `transfers`, следующая задача; DS-021 закрыт этим решением как out-of-scope). Правило удаления в рамках `transfers` до появления soft delete — уточняется В-19.

## Батч 5 (2026-10-07) — края отката, «ждёт поставку», удаления до soft delete
- **В-17:** «Отменить проведение», когда единицу увёз дальше другой документ? → **Ответ:** a) откат в обратном порядке: система не даёт отменить документ и называет более поздний со ссылкой; оплата заказа и уход остатка в минус откат НЕ блокируют (остаток в минус с предупреждением, итог заказа пересчитывается, «Оплачен» остаётся) → DS-023
- **В-18:** «Ждёт поставку» — сейчас или следом? → **Ответ:** a) отдельной задачей после перемещений; здесь только документ «поставщик → склад», связь со строками товаров заказа не закладываем → DS-024
- **В-19:** Удаление до появления soft delete? → **Ответ:** a) заказ с документами не удаляется, пока документы не отменены/не откатаны; сообщение перечисляет мешающие документы. Дополнительно (из ответа на первую редакцию): сам документ можно удалить только в статусе «Заявка» или «Отменён»; проведённый сначала «Отменить проведение», затем «Отменить», после этого удалить → DS-025
- **В-20:** Удаление единицы оборудования и архивирование склада? → **Ответ:** a) единицу нельзя убрать из заказа и удалить из справочника, пока она в незавершённом документе; единицу с завершёнными документами удалить из справочника нельзя; склад нельзя архивировать, пока на нём числится оборудование или есть незавершённые документы с ним → DS-026

## Батч 6 (2026-10-07) — совместимость, UI-scope, миграция, переименования, время

- **В-24:** Время и фильтр по дате? → **Ответ (дословно):** «Твой пояс нужно добавить как настройку у каждого пользователя он будет свой, так как если груст находится в Москве, то надо показывать московское время. Края (inferred, ответ не покрывает): единственная колонка считается последней; заказа без колонки не бывает (`tasks.column_id` NOT NULL, `:27`); при равных `position` — колонка с большим `id`. Признак `columns.is_final` в миграции не используется (в сиде колонок последняя «Готово» одновременно и `is_final`, но администратор может это изменить).
