§1. Суть задачи

Любое удаление в системе становится восстановимым: запись уходит в раздел «Удалённые», откуда администратор возвращает её одной кнопкой. Для администратора; исполнитель удалённого не видит.

Бизнес (что делает пользователь/процесс):

  1. 7Администратор удаляет запись любого из 11 видов — заказ, документ перемещения, колонку доски, клиента, единицу оборудования, товар, услугу, категорию, тип оборудования, склад, поставщика — и обязательно указывает причину (§8.2) — DS-001, DS-020.
  2. 8Администратор открывает раздел «Удалённые» (§8.1), выбирает вкладку вида записей, видит что удалено, кем, когда и почему, нажимает «Восстановить» — DS-011.
  3. 9При восстановлении заказа система сообщает, что изменилось: не хватает товара на складе, колонка заменена, клиент или оборудование в удалённых — DS-005, DS-016.
  4. 10В справочниках «В архив» остаётся отдельным действием: архивная запись видна в справочнике, удалённая — только в «Удалённых» — DS-009.

Логика (правила системы):

  1. 11Удалённая запись физически остаётся в базе с отметкой «кто, когда, почему»; хранится бессрочно, окончательного удаления нет — DS-012, DS-030.
  2. 12Удалённая запись не видна нигде, кроме раздела «Удалённые», и не выбирается в новых записях; там, где на неё уже ссылаются действующие заказы и документы, она показывается с пометкой «удалён» — DS-010, DS-014.
  3. 13Удалить можно всегда, ссылки удалению не мешают; исключения — то, что влияет на учёт: проведённый документ перемещения, товар с остатком, склад с товаром, оборудованием или незавершёнными перемещениями, клиент и единица оборудования, пока оборудование на нашем складе, в пути или в незавершённом документе, непустая колонка доски — DS-014, DS-018, DS-019, DS-021, DS-041.
  4. 14Заказ: при удалении товары возвращаются на склад, при восстановлении списываются снова; документы перемещения заказа остаются действующими, остатки и местоположение оборудования по ним не меняются — DS-004, DS-005, DS-006, DS-008.
  5. 15Клиент уходит в удалённые и возвращается вместе со своим оборудованием — DS-015.
  6. 16Название удалённой записи свободно; восстановление при занятом названии — отказ — DS-017.

6а. Остаток, появившийся у удалённого товара или на удалённом складе позже, виден в отчёте «Остатки» с пометкой «удалён» — DS-042. 6б. Удалённый документ перемещения не мешает сменить клиента заказа; после смены клиента такой документ не восстанавливается — DS-040.

  1. 17Время: deleted_at хранится в UTC (timestamptz); показывается и фильтруется по часовому поясу пользователя, формат «ДД.ММ.ГГГГ ЧЧ:ММ» — DS-025 (краткий дубль §3).
  2. 18Конкурентный доступ: удаляем запись → атомарный UPDATE с условием «ещё не удалена», повтор → 404; восстанавливаем → атомарный UPDATE с условием «удалена», повтор → 409; заказ — под блокировкой строки заказа; документ перемещения — дополнительно по version — DS-024 (краткий дубль §3).

Техника (API/данные/интеграции):

  1. 19Данные: три новые колонки (deleted_at, deleted_by, delete_reason) на 11 существующих таблицах, у equipment — ещё deleted_with_client; новых таблиц нет; уникальные индексы названий четырёх справочников становятся частичными (§4).
  2. 20API: 11 адресов удаления (9 существующих меняют поведение, 2 новых) и 11 новых адресов восстановления (§6.1–§6.22); GET /api/v1/deleted и GET /api/v1/deleted/summary для раздела «Удалённые» (§6.23, §6.24); служебная уборка автотестов (§6.25); условие «не удалён» во всех существующих адресах чтения и выбора (§6.26).
  3. 21Новый пакет internal/features/softdelete — только чтение раздела «Удалённые» и страница /deleted; само удаление и восстановление остаются в пакетах-владельцах (board, transfers, clients, catalog, equipmenttypes, warehouses, suppliers).
  4. 22Внешних систем нет.

UI (графическая часть):

  1. 23Новый пункт меню «Администрирование → Удалённые» (/deleted, только admin) — страница с 11 вкладками, фильтрами и кнопкой «Восстановить» в каждой строке (§8.1).
  2. 24Общее окно «Удаление» с обязательным полем «Причина» — заменяет нынешние подтверждения удаления на всех экранах (§8.2).
  3. 25Доска и карточка заказа: удаление с причиной; пометки «удалён» у клиента, оборудования, услуги, товара (§8.3).
  4. 26«Перемещения»: пометка «заказ удалён» в списке и в документе; удаление документа с причиной (§8.4).
  5. 27Справочники (клиенты, оборудование, каталог, типы оборудования, склады, поставщики): кнопка «Удалить» рядом с «В архив»; у складов и поставщиков — впервые (§8.5).

Out-of-scope:

  1. 28Сотрудники — не удаляются, как и сейчас: только «неактивен» (решение пользователя, DS-002).
  2. 29Части заказа (услуга, товар в услуге, запись о работе, вложение, оборудование в заказе) — удаляются как сейчас, безвозвратно: это правка заказа; восстановим только заказ целиком (решение пользователя, DS-002).
  3. 30Окончательное удаление («удалить навсегда») и автоматическая очистка по сроку — не делаем, хранение бессрочное (решение пользователя, DS-012).
  4. 31История повторных удалений одной записи — не ведётся: хранится только последнее удаление, при восстановлении отметка стирается (DS-030).
  5. 32Статус заказа «ждёт поставку» — отдельная задача (docs/plan.md D78).

§3. Нефункциональные требования

Конкурентность (по операциям):

  1. 34Удаление записи (все 11 видов):
    • 35один UPDATE с условием deleted_at IS NULL; затронуто 0 строк → запись уже удалена либо не существует → 404 — DS-024
    • 36два администратора удаляют одну запись одновременно: первый получает 200, второй — 404; причина второго не записывается
  2. 37Восстановление записи (все 11 видов):
    • 38один UPDATE с условием deleted_at IS NOT NULL; затронуто 0 строк при существующей записи → 409 NOT_DELETED — DS-024
  3. 39Удаление и восстановление заказа:
    • 40под блокировкой строки заказа (LockTask, FOR UPDATE) — та же блокировка, что у действующего удаления и правки заказа; возврат и списание товара — в той же транзакции, порядок блокировок «заказ → product_stock» не меняется (docs/plan.md D75) — DS-004, DS-005
    • 41правка заказа, пришедшая после удаления, → 404 TASK_NOT_FOUND — DS-026
  4. 42Удаление и восстановление документа перемещения:
    • 43оптимистичная блокировка по version (as-is): устаревшая версия → 409 TRANSFER_VERSION_CONFLICT; восстановление заявки занимает единицы под блокировкой строк equipment (FOR NO KEY UPDATE, as-is порядок «документ → equipment») — DS-018
  5. 44Создание документа по заказу одновременно с удалением заказа:
    • 45создание документа держит на заказе FOR KEY SHARE и проверяет deleted_at IS NULL под ней: удаление выиграло → 409 TASK_DELETED; создание выиграло → документ остаётся у удалённого заказа (допустимо, DS-006) — DS-007
  6. 46Удаление склада и товара с остатком:
    • 47проверка остатка и запись отметки — в одной транзакции под блокировкой строк product_stock (товар) либо строки warehouses (склад); приход, пришедший позже, получает 400 not_found по удалённой записи — DS-021
  7. 48Удаление колонки доски:
    • 49под блокировкой списка колонок (as-is транзакция удаления колонки): перенос заказа в колонку и её удаление не расходятся — перенос в удалённую колонку → 404 COLUMN_NOT_FOUND — DS-019
  8. 50Версионирование справочников: отдельной колонки version у клиентов, оборудования, каталога, складов, поставщиков нет и не вводится — правка действующей записи остаётся last-write-wins (as-is); правка удалённой → 404 — DS-026

Аудит:

  • 51на записи хранится последнее удаление: кто (deleted_by), когда (deleted_at), почему (delete_reason); читается в разделе «Удалённые» — DS-030
  • 52при восстановлении три поля очищаются; факт удаления и восстановления пишется в журнал приложения (slog, уровень info: вид записи, идентификатор, пользователь, действие) — DS-030
  • 53чтение раздела «Удалённые» не журналируется

Время/таймзоны:

  • 54хранение: deleted_at — timestamptz, UTC, время сервера базы (now()) — DS-025
  • 55интерпретация периода фильтра «Удалено с / по» — по часовому поясу пользователя (pkg/timezone): «за 08.10.2026» = с 00:00 до 24:00 этого дня в поясе пользователя — DS-025
  • 56показ — «ДД.ММ.ГГГГ ЧЧ:ММ» в поясе пользователя (KT.time)
  • 57порядок в списке — по deleted_at по убыванию, при равенстве — по id

Метрики/таймстемпы:

  • 58единственный новый таймстемп — deleted_at; отчётов по длительностям и оповещений нет
  • 59счётчики по вкладкам раздела «Удалённые» — GET /api/v1/deleted/summary (§6.24)

Abuse cases (инсайдерские риски — вход для adversarial E2E TD-4):

  1. 67Исполнитель вызывает адрес удаления, восстановления или списка удалённого напрямую → 403 «Нет доступа» до любого чтения записи — DS-003.
  2. 68Исполнитель открывает карточку, печатную форму или вложение удалённого заказа по прямой ссылке → 404, как для несуществующего — DS-010, DS-013.
  3. 69Удалённая запись подставляется по идентификатору в новый заказ или документ в обход выпадающего списка → 400 not_found — DS-014.

§5. Статусная модель

Состояние записи складывается из двух независимых признаков: удалена ли она (deleted_at) и, у справочников с архивом, в архиве ли она (is_active). Собственные статусы заказа (колонка доски) и документа перемещения (requested, in_transit, received, cancelled) этой задачей не меняются.

Состояния: active — действует; archived — в архиве (только products, services, catalog_categories, equipment_types, warehouses, suppliers); deleted — удалена (в базе это deleted_at IS NOT NULL при любом is_active). Терминальных состояний нет — DS-012.

§6. API

Режим B «API + фронтенд». Базовый URL стенда: http://localhost:8080. Авторизация — сессионная cookie sid (плейсхолдер <SID>). Копируй curl в терминал или в Postman: Import → Raw text. Тело ошибки — формат pkg/errorspkg: {code, message, details}; при 400 — details.fields[] с name и message. Все ключи — snake_case, URL — kebab-case (CLAUDE.md §API-1). Текст отказа в доступе единый — «Нет доступа». Единые правила всех адресов этой задачи (DS-028): удаление — DELETE /api/v1/{ресурс}/:id с JSON-телом {reason}; восстановление — POST /api/v1/{ресурс}/:id/restore без тела; список удалённого — GET /api/v1/deleted. §6.1–§6.22 — пара «удалить / восстановить» на каждый из 11 видов записей; §6.23–§6.24 — раздел «Удалённые»; §6.25 — служебная уборка автотестов; §6.26 — изменения остальных существующих адресов.
