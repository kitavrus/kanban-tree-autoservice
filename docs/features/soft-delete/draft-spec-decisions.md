# Draft-spec decisions: Мягкое удаление с восстановлением (soft-delete)

Режим: обычный (новая спека). Черновик пользователя — 2026-10-07. Номера DS присваиваются при записи `draft-spec.md`.

## Батч 0 (2026-10-08) — intake: факты as-is по коду (вопросов не было)

- **Удаление заказа сейчас:** `DELETE /api/v1/tasks/:id`, только admin (`internal/features/board/routes.go:38`, `tasks_service.go` `TaskService.Delete`). В одной транзакции: блокировка заказа → `deleteTaskTransfers` (неотменённые документы → 409 `TASK_HAS_TRANSFERS`, отменённые удаляются) → `StockEngine.Reconcile(false)` возвращает на склад ВСЕ товары заказа → строка `tasks` удаляется физически; после commit удаляются файлы вложений с диска.
- **FK от `tasks`:** CASCADE — `subtasks` (и далее `subtask_products`, `subtask_logs`), `task_stock`, `task_equipment`, `task_attachments`; SET NULL — `stock_movements.task_id`; RESTRICT — `transfers.task_id`.
- **Архив (`is_active`) уже есть:** `users` (удаления нет вовсе), `equipment_types`, `catalog_categories`, `products`, `services`, `warehouses`, `suppliers`.
- **Архива нет, удаление физическое:** `tasks`, `transfers` (только «Заявка»/«Отменён», admin), `clients`, `equipment`, `columns`, части заказа (`subtasks`, `subtask_products`, `subtask_logs`, `task_attachments`, `task_equipment`).
- **Физическое удаление есть и у справочников с архивом:** `equipment_types`, `catalog_categories`, `products`, `services` (маршруты `DELETE`, admin).
- **Читатели `tasks`, которых коснётся фильтр «не удалён»:** `board` (доска, карточка, «Остатки», позиции, колонки, вложения), `clients` (история оборудования, проверки удаления), `transfers`, `executorpayouts` («Выплаты»), `users`, `seeddemo`.
- **Уже закрыто пользователем (transfers DS-025, не переспрашивать):** удалить можно только то, что не влияет на учёт; проведённый документ сначала отменяют; при восстановлении остатки и местоположение оборудования не меняются.
- **E2E-уборка:** `e2e/fixtures/test.ts` `_boardCleanup` → `adminApi.purgeTask` (`e2e/fixtures/auth.ts:590`) удаляет физически.

## Батч 1 (2026-10-08)

- **В-1:** Что именно удаляем «мягко» в этой задаче? → **Ответ:** d) всё, включая справочники, где уже есть архив (товары, услуги, категории, типы оборудования). → DS (охват). Следствие: Tier L → мастер-спека + части S/M по образцу `transfers`.
- **В-2:** Кто удаляет и кто восстанавливает? → **Ответ:** a) и удаляет, и восстанавливает только администратор. → DS (права).
- **В-3:** Товары заказа на складе при удалении и восстановлении? → **Ответ:** a) при удалении товары возвращаются на склад (как сейчас), при восстановлении списываются снова; не хватает — заказ восстанавливается с предупреждением о нехватке. → DS (остатки).
- **В-4:** Документы перемещения удаляемого заказа? → **Ответ:** c) заказ удаляется с любыми документами; документы остаются в «Перемещениях» с пометкой «заказ удалён», остатки и местоположение оборудования не меняются. → DS (документы). ОСОЗНАННОЕ ИЗМЕНЕНИЕ ПРАВИЛА: отменяет 409 `TASK_HAS_TRANSFERS` и удаление отменённых документов вместе с заказом (transfers DS-025 в части заказа, DS-050, `docs/plan.md` D75/D78). Следствия подтверждаются в батче 2 (В-6).

## Батч 2 (2026-10-08)

- **В-5:** Как удаление соотносится с архивом (`is_active`) в справочниках? → **Ответ:** a) дополняет: «В архив» остаётся как есть (запись видна в справочнике, не предлагается в выборе), «Удалить» становится восстановимым — запись уходит в «Удалённые». → DS (два независимых состояния: архив и удалён).
- **В-6:** Что можно делать с документами перемещения удалённого заказа? → **Ответ:** a) начатое можно довести (принять, откатить, отменить); создавать новые документы по удалённому заказу нельзя; при восстановлении заказа документы остаются как есть. → DS.
- **В-7:** Где виден удалённый заказ, кроме списка удалённых? → **Ответ:** a) нигде: исчезает с доски, из поиска, из «Выплат», из истории оборудования и итогов; остаётся только в «Удалённых» и пометкой у своих документов перемещения. → DS.
- **В-8:** Как смотреть удалённое и восстанавливать? → **Ответ:** a) один раздел «Удалённые» с вкладками по видам (заказы, перемещения, клиенты, оборудование, каталог и т. д.), у каждой строки — «Восстановить». → DS.

## Батч 3 (2026-10-08)

- **В-9:** Сколько хранится удалённое, нужно ли «удалить навсегда»? → **Ответ:** a) хранится бессрочно, окончательного удаления нет — восстановить можно всегда. → DS. Следствие (inferred): файлы вложений удалённого заказа с диска не стираются; фоновая уборка сирот не должна считать их сиротами.
- **В-10:** Удаление записи, на которую ссылаются другие? → **Ответ:** a) удалить можно всегда: в заказах и документах запись остаётся видна с пометкой «удалён», в новых выбрать её нельзя; оборудование клиента уходит в удалённые вместе с клиентом. → DS. ОСОЗНАННОЕ ИЗМЕНЕНИЕ ПРАВИЛ: снимаются запреты удаления по ссылкам (клиент с заказами, единица с документами — `EQUIPMENT_HAS_TRANSFERS`, transfers DS-026 в части удаления из справочника).
- **В-11:** Восстановление заказа, когда связанное изменилось? → **Ответ:** a) восстанавливаем всегда с предупреждением: заказ встаёт в первую колонку доски, удалённые клиент и оборудование остаются с пометкой «удалён». → DS.
- **В-12:** Название удалённой записи занято или свободно? → **Ответ:** a) свободно: можно создать новую с тем же названием; при восстановлении старой, если название занято, — отказ «Название занято — переименуйте действующую запись». → DS (уникальность — только среди неудалённых).

Унаследовано без вопроса (transfers DS-025, закрыто пользователем): документ перемещения удаляется только в статусах «Заявка» и «Отменён»; проведённый сначала откатывают и отменяют. Теперь это удаление мягкое; восстановление документа остатки и местоположение не меняет.

## Батч 4 (2026-10-08)

- **В-13:** Части заказа (услуга, товар в услуге, запись о работе, вложение, оборудование в заказе) делаем восстановимыми? → **Ответ:** a) нет: это правка заказа, части удаляются как сейчас; восстановимо только удаление заказа целиком — он возвращается со всеми частями. → DS.
- **В-14:** Сотрудники и колонки доски? → **Ответ:** a) сотрудников по-прежнему не удаляем — только «неактивен»; колонки доски удаляются с восстановлением. → DS.
- **В-15:** Причина удаления и состав списка «Удалённые»? → **Ответ:** c) причина обязательна — без неё удалить нельзя. → DS. Уточнение оркестратора: причина обязательна для любого удаления (все виды записей); в «Удалённых» — что / кто / когда / причина. Inferred (на проверку): оборудование, ушедшее в удалённые вместе с клиентом, наследует причину клиента и помечается «удалено вместе с клиентом».
- **В-16:** Склад с товаром/оборудованием и товар с ненулевым остатком? → **Ответ:** a) нельзя: сначала переместить или списать остаток; удаляются только склад без товара, оборудования и незавершённых перемещений и товар с нулевым остатком. → DS. Исключение из правила В-10=a («удалить можно всегда»).

Решено без вопроса пользователю (оркестратор согласовал): уборка автотестов (`_boardCleanup` → `purgeTask`) — открытый технический пункт; рекомендация — служебный путь физической уборки тестовых данных, недоступный в рабочем режиме.
