§1. Суть задачи

Документ «Перемещение» получает направление и контрагента: клиент и поставщик становятся точками маршрута. Для администратора и исполнителя.

Бизнес (что делает пользователь/процесс):

  1. 1Принимает оборудование клиента в ремонт документом «клиент → склад», всегда по заказу; если клиент принёс сам — создаёт и принимает одним действием (§8.2 → §8.1) — DS-002, DS-012, DS-013.
  2. 2Возвращает оборудование клиенту документом «склад → клиент» по заказу; «Принять» нажимает наш сотрудник, когда клиент получил (§8.1) — DS-013.
  3. 3Администратор заказывает товары у поставщика документом «поставщик → склад» и принимает по факту: меньше или больше заказанного (§8.1) — DS-015.
  4. 4Исполнитель создаёт и проводит документы с клиентом и видит в списке только их (§8.1) — DS-018.
  5. 5Ищет документы за период по дате создания (§8.1) — DS-034.

Логика (правила системы):

  1. 6Четыре направления direction: client_to_warehouse, warehouse_to_client, warehouse_to_warehouse, supplier_to_warehouse; после создания не меняется — DS-002.
  2. 7Состав строк по направлениям — DS-004:
    • 8client_to_warehouse: только единицы оборудования этого заказа;
    • 9warehouse_to_client: только единицы оборудования этого заказа (товар с ценой добавит часть 5, DS-011);
    • 10warehouse_to_warehouse: единицы оборудования любых клиентов + товары (как в ядре);
    • 11supplier_to_warehouse: только товары, без цен — DS-016.
  3. 12Для направлений с клиентом заказ обязателен; клиент документа выводится сервером из заказа; единица строки должна входить в оборудование заказа — DS-012, DS-035.
  4. 13Три шага «Заявка → В пути → Получено» для всех направлений — DS-013.
  5. 14При добавлении единицы в заказ склад больше не выбирается: единица остаётся там, где числится; на склад её приводит документ «клиент → склад» — DS-045.
  6. 15Приход от поставщика: остаток растёт на факт при приёмке; при отправке движений нет; на «Остатках» в колонке «в пути» учитывается — DS-040, DS-047.
  7. 16Документ чужого направления для исполнителя — «не найдено» (404) — DS-042.
  8. 17Время: хранение UTC; границы дня фильтра «период» — по часовому поясу пользователя (users.timezone, часть 2), сервер переводит их в UTC и применяет к created_at — DS-034; показ времени — общим форматтером по поясу пользователя (DS-031 — контекст, реализуется в user-timezone).
  9. 18Конкурентный доступ (краткий дубль §3):
    • 19правка и переходы документа → optimistic lock version + 409, как в ядре (DS-048 — контекст, реализуется в transfers-core);
    • 20отправка «клиент → склад» → guard «единица у клиента» под FOR NO KEY UPDATE строки equipment (as-built, D75; не FOR UPDATE); отправка «склад → клиент» → guard «единица на складе отправления» — DS-013;
    • 21приход от поставщика → FOR UPDATE строк product_stock склада назначения в порядке product_id — DS-040;
    • 22удаление заказа при существующих документах → 409, заказ не удаляется — DS-012.

Техника (API/данные/интеграции):

  1. 23transfers: новые direction, task_id, client_id, supplier_id; from_warehouse_id и to_warehouse_id становятся необязательными по направлению; CHECK маршрута (§4.1).
  2. 24stock_movements.reason: три новых значения (§4.3).
  3. 25API /api/v1/transfers: дельты семи endpoint'ов ядра (§6.1–§6.7); дельта карточки заказа (§6.8); прочие дельты (§6.9).
  4. 26Пакет internal/features/transfers; читает suppliers, task_equipment, users.timezone.

UI (графическая часть):

  1. 27«Перемещения» (/transfers): виден исполнителю; меню выбора направления; поля «Заказ» и «Поставщик»; фильтры «Направление», «Поставщик», «Заказ», «Период» (§8.1).
  2. 28Карточка заказа: блок «Перемещения заказа» с кнопками «Принять от клиента» и «Вернуть клиенту»; из формы добавления единицы убран select «Склад приёма» (§8.2).

Out-of-scope:

  1. 29Товар с ценой в документе «склад → клиент», сумма накладной, итог заказа — часть 5 transfers-sales (DS-011, DS-014, DS-038, DS-039).
  2. 30«Отменить проведение», удаление документа, человеческое сообщение при удалении заказа с документами и удаление отменённых документов вместе с заказом — часть 6 transfers-revert (DS-017, DS-025, DS-050).
  3. 31Статус товара заказа «ждёт поставку» и заказ у поставщика под заказ клиента — отдельная задача после мастер-спеки; связь прихода от поставщика со строками товаров заказа не закладывается (DS-024).
  4. 32Закупочные цены; создание товара каталога из документа — нет (DS-016).
  5. 33Возврат товара от клиента — нет: от клиента принимается только его оборудование (DS-004).

Конкурентность (К-3 — по операциям):

  1. 40Правка и переходы документа: без изменений относительно ядра — обязательный version, сверка до статуса, 409 TRANSFER_VERSION_CONFLICT / TRANSFER_STATUS_CONFLICT (DS-048 — контекст, реализуется в transfers-core).
  2. 41Отправка документа с клиентом:
    • 42client_to_warehouse: под FOR NO KEY UPDATE (as-built, D75; не FOR UPDATE) строки equipment — единица at_client; иначе 409 TRANSFER_EQUIPMENT_NOT_AT_SOURCE — DS-013
    • 43warehouse_to_client: единица at_warehouse на складе отправления; иначе тот же 409 — DS-013
  3. 44Создание и приём одним действием (receive: true): создание, отправка и приёмка — одна транзакция; при любой ошибке не создаётся ничего — DS-013
  4. 45Приход от поставщика: при приёмке Lock Order — transfers FOR UPDATE → строки product_stock склада назначения FOR UPDATE в порядке product_id; двойной «Принять» → второй 409, остаток вырос один раз — DS-015, DS-040
  5. 46Удаление заказа с документами: проверка в транзакции удаления; есть хоть один документ заказа → 409 CONFLICT, ничего не удалено (FK task_id RESTRICT — страховка) — DS-012
  6. 47Добавление единицы в заказ: местоположение больше не пишется — гонки с документом нет — DS-045
  7. 48as-built (D75) — блокировки и их порядок: документ (FOR UPDATE) → заказ (FOR KEY SHARE — при создании/правке документа с клиентом, до чтения оборудования заказа) → product_stock (FOR UPDATE, по product_id) → equipment (FOR NO KEY UPDATE, по id); при удалении заказа блокируется только заказ, его документы не блокируются
  8. 49as-built (D84) — смена клиента заказа: пока у заказа есть хотя бы один документ в любом статусе (включая «Получено» и «Отменён»), PUT /api/v1/tasks/:id с другим client_id → 409 TASK_CLIENT_LOCKED_BY_TRANSFERS «У заказа есть перемещения — сменить клиента нельзя», details.transfer_ids — номера по возрастанию; проверка под блокировкой заказа, до любых изменений (client_id документа — снимок клиента заказа)
