# Draft-spec decisions: Закупки по дефициту (purchase-orders)

## Батч 0 — план, согласован 2026-10-22 (вопросы не задавались)
- Источник: shortage-order-plan.md (разделы «Решения пользователя», «Решения второго круга»). Все решения плана — closed DS с источником «план, согласован 2026-10-22».

## Батч 1 (2026-10-22)
- **В-1:** Совместимость (§CM-1) → **Ответ:** MVP — живых данных нет, таблицы/адреса меняем свободно → DS-030
- **В-2:** UI-scope (§US-1) → **Ответ:** swagger:yes; adaptive:full для кабинета поставщика, экраны «Закупки» — минимальная проверка (overflow-смок); themes:both → DS-031
- **В-3:** Конкурентность → **Ответ:** version + 409 на заказе (правка черновика, send/recall/pick-up/cancel); у строки поставщика своя version (409 второму); «Собрано» vs «Отозвать» — выигрывает первое, второй 409 → DS-032
- **В-4:** Время/TZ → **Ответ:** хранение UTC (timestamptz); показ в поясе смотрящего (users.timezone, по умолчанию Asia/Almaty, у поставщика тоже, может сменить); фильтра по дате нет, только по статусу → DS-033
## Батч 2 (2026-10-22)
- **В-5:** Когда править строки → **Ответ:** b) можно и в sent; поставщик видит изменения сразу; ответ по изменённым строкам сбрасывается → DS-034
- **В-6:** Судьба ответа поставщика при recall/повторной отправке → **Ответ:** a) сохраняется; у изменённых/добавленных нами строк — сбрасывается; отозванный (draft) пропадает из кабинета до повторной отправки → DS-035
- **В-7:** Отмена/удаление → **Ответ:** причина отмены обязательна 1–500; отменённый заказ из кабинета поставщика СКРЫВАЕТСЯ (→ причина видна только нам, inferred разрешение противоречия, подтверждается в батче 3); удаление — только draft, мягко, раздел «Удалённые» с восстановлением → DS-036, DS-037
- **В-8:** «Собрано» → **Ответ:** только когда по каждой строке заполнено supplier_qty (0 — ответ), цена обязательна при qty>0; отменить «Собрано» поставщик не может; «Забрали» — только после ready (для поставщика) → DS-038
## Батч 3 (2026-10-22)
- **В-9:** Правка после ready / что считается изменённой строкой / причина отмены → **Ответ:** после ready строки read-only; «изменённая» = ЛЮБАЯ правка, включая примечание к заказу (трактовка — уточняется в батче 4); причину отмены видим только мы → DS-039, DS-040, DS-041
- **В-10:** Поставщик без входа / архив поставщика → **Ответ:** отправить без входа можно; для поставщика без активного входа «Забрали» разрешено прямо из sent; архив/удаление поставщика с незакрытыми закупками — запрет с ошибкой со списком номеров → DS-042, DS-043
- **В-11:** Учётки поставщика → **Ответ:** несколько входов на поставщика; создаёт только admin на «Пользователи»; при блокировке сессия обрывается сразу (as-is: middleware/auth.go resolve убивает сессию неактивного); поставщик видит номер, дату отправки, примечание заказа, наше имя и телефон (FIRM_NAME/FIRM_PHONE); reason строки и наши цены не видит → DS-044, DS-045, DS-046
- **В-12:** Валидации → **Ответ:** qty >0…99999.999 (3 знака); supplier_qty 0…99999.999, больше просимого можно (подсветка); supplier_price 0…9999999.99; supplier_note ≤500; note ≤1000; дубль запчасти нельзя — складываем количество; ≤200 строк → DS-047
## Батч 4 (2026-10-22)
- **В-13:** Трактовка сброса при правке примечания → **Ответ:** a) правка строки сбрасывает ответ только этой строки; правка примечания заказа ответы НЕ сбрасывает, у поставщика заказ помечается «Изменён», новое примечание подсвечивается; у строк со сброшенным ответом — пометка «Изменено заказчиком» → DS-048
- **В-14:** «Открытые» для подсказки → **Ответ:** только sent и ready (черновики не считаем); количество без вычета, галочка снята → DS-049
- **В-15:** Права исполнителя → **Ответ:** отменить — admin и executor; удаление черновика, восстановление, окончательное удаление — только admin; править/отменять executor может только СВОИ (created_by = он); admin — все заказы (естественное прочтение; inferred, вынесено в open для подтверждения) → DS-050, DS-051
- **В-16:** Аудит → **Ответ:** a) у заказа кто/когда создал, отправил, забрал, отменил; у строки — кто из поставщика ответил последним и когда; отдельного журнала нет → DS-052
## Батч 5 — update (2026-10-22)
- **DS-060:** Видимость заказов для executor → **Ответ:** «Исполнитель видит только свои». Admin — любые заказы, все действия; executor видит в списке и открывает ТОЛЬКО созданные им (чужой id → 404, как у поставщика) → DS-060 open → closed (формулировка переписана)
- **Следствие (выведено, не спрашивалось):** подсказка «уже в открытом заказе» считает ВСЕ открытые заказы, включая чужие (иначе дубли закупок); номер чужого заказа показывается без ссылки (`is_own`=false) → DS-078 (inferred) — вынесено в «что перепроверить»
## Батч 6 — update (2026-10-22)
- **DS-078:** Подсказка «уже в открытом заказе» и чужие заказы → **Ответ пользователя:** для executor подсказка учитывает ТОЛЬКО его собственные заказы (`s:sent`, `s:ready`); для admin — все открытые. Номер DS сохранён, формулировка переписана, источник «батч 6 (update, пользователь)». Принятый риск — возможны дубли закупок у разных исполнителей; поле `is_own` убрано из §6.10 (каждый заказ в подсказке доступен смотрящему) → DS-078
