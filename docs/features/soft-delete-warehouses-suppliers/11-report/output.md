# Отчёт: soft-delete-warehouses-suppliers (часть 6 из 6 мастера soft-delete)

## Что сделано

У складов и поставщиков впервые появилось действие «Удалить» — с обязательной причиной и восстановлением из раздела «Удалённые» (вкладки «Склады» и «Поставщики»); «В архив» остаётся отдельным действием. Склад удаляется только пустым: без товара, оборудования и действующих незавершённых перемещений; последний активный склад удалить нельзя. Мягко удалённые заявки больше не мешают ни удалить склад, ни отправить его в архив. В документах удалённые склад и поставщик остаются видны с пометкой «удалён», в новых выбрать их нельзя. Заявку с удалённым складом нельзя отправить, восстановить и нельзя отменить проведение её документа; удалённый поставщик не мешает довести начатый документ, но заявку с ним восстановить нельзя. Если на удалённом складе всё же появился остаток или долг (возврат из заказа, перенос заказа по колонкам), он виден в отчёте «Остатки» с пометкой и его можно только списать. Отчёт «Остатки» теперь показывает архивные и удалённые склады, на которых есть остаток.

Технически: миграция `0023_soft_delete_warehouses_suppliers` (поля удаления, частичные уникальные индексы названий, `default_warehouse_id()` только по действующим складам), `DELETE`/`POST …/restore` для складов и поставщиков, источники в пакете `softdelete`, служебная уборка, поля `from_warehouse_is_deleted`, `to_warehouse_is_deleted`, `supplier_is_deleted`, `is_deleted` у склада карточки, `is_archived` у склада и строки «Остатков», удалённые записи в демо-данных.

## Known issues / отложено

- Решения оркестратора по ревью (пользователь в автономном режиме), вносятся в спеку отдельным коммитом документов: отказ `WAREHOUSE_DELETED` при увеличении количества; показ архивного товара с остатком на удалённом складе; код `WAREHOUSE_DELETED_WRITE_OFF_ONLY`.
- Отчёт «Остатки» показывает архивные склады с ненулевым остатком — изменение действующего вида отчёта, пользователь его отдельно не подтверждал.
- Перенос заказа по колонкам и восстановление заказа могут создать долг на удалённом складе — допущено осознанно: долг виден в «Остатках» и списывается.
- Причина каскада E2E в первом прогоне не установлена; в коде части причин не найдено, повторные прогоны зелёные.
- Low из ревью: новые ветки интерфейса (текст отказа у строки заказа, бейдж «в архиве» в «Остатках») покрыты только тестами API, без E2E; у строки архивного товара в «Остатках» минимум и потребность не обнулены; ветка повтора выбора склада по умолчанию без теста гонки; разный порядок блокировок товаров и складов между перемещениями и доской/каталогом (теоретическая взаимоблокировка); три копии цикла блокировки складов; история клиента показывает удалённые склады без пометки; откат миграции 0023 упадёт при одноимённых удалённой и действующей записях (режим MVP).
- Уборка тестовых данных в E2E оставляет около 90 записей за прогон (утечка только на одноразовом стенде).
