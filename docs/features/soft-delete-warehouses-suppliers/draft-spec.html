§1. Суть задачи

Склады и поставщики получают восстановимое удаление рядом с архивом. Для администратора.

Бизнес (что делает пользователь/процесс):

  1. 1Администратор удаляет пустой склад с причиной; склад с товаром, оборудованием или незавершёнными перемещениями удалить нельзя — система называет, что мешает (§8.1) — DS-021, DS-020.
  2. 2Администратор удаляет поставщика с причиной — документы поставщика остаются и показывают бейдж «удалён» (§8.1, §8.3) — DS-014.
  3. 3Администратор по-прежнему отправляет склад и поставщика в архив — отдельное действие (§8.1) — DS-009.
  4. 4Администратор восстанавливает склад или поставщика из «Удалённых» — активным либо архивным, каким был (§8.2) — DS-009.

Логика (правила системы):

  1. 5Склад не удаляется, пока на нём есть товар с ненулевым остатком, числится оборудование либо есть действующий документ в «Заявка» или «В пути» с этим складом — DS-021. Удалённых единиц на складе быть не должно (удалить можно только оборудование, находящееся у клиента, DS-041); проверка всё равно считает все единицы склада без условия по удалению — как страховка.

1а. Остаток, появившийся на удалённом складе позже (возврат товара из заказа по строке этого склада), виден в отчёте «Остатки» с пометкой «удалён» и может быть списан корректировкой — DS-042.

  1. 6Последний активный склад не удаляется — системе нужен склад по умолчанию — DS-021.
  2. 7Поставщик удаляется при любых документах; в документах остаётся с бейджем «удалён» — DS-014.
  3. 8Название удалённого склада и поставщика свободно; восстановление при занятом названии — отказ — DS-017.
  4. 9Удалённые склад и поставщик не выбираются в новых документах, заказах, остатках; для обычных адресов не существуют — DS-014, DS-026.
  5. 10Архив и удаление независимы; при восстановлении признак архива прежний — DS-009.
  6. 11Время: deleted_at — UTC (timestamptz), показ и фильтр — по поясу пользователя, «ДД.ММ.ГГГГ ЧЧ:ММ» — DS-025 (краткий дубль §3).
  7. 12Конкурентный доступ: удаляем склад → одна транзакция под блокировкой активных складов (та же, что у архивирования) с проверками и записью; удаляем поставщика → один UPDATE с условием «ещё не удалён»; восстанавливаем → условие «удалён», название держит частичный индекс — DS-024 (краткий дубль §3).

Техника (API/данные/интеграции):

  1. 13Данные: по три новые колонки в warehouses и suppliers; два уникальных индекса названий становятся частичными; функция базы default_warehouse_id() перестаёт выбирать удалённые склады (§4).
  2. 14API: четыре новых адреса — удаление и восстановление склада и поставщика (§6.1–§6.4); новые поля-признаки в ответах документов и карточки заказа, условие «не удалён» в списках и выборе, виды раздела «Удалённые» и служебной уборки, новая серверная форма удаления склада (§6.5).
  3. 15Пакеты: internal/features/warehouses, internal/features/suppliers, internal/features/transfers, internal/features/board, internal/features/catalog, internal/features/softdelete.
  4. 16Внешних систем нет.

§3. Нефункциональные требования

Конкурентность (по операциям):

  1. 25Удаление склада:
    • 26одна транзакция: действующие активные склады блокируются FOR UPDATE по возрастанию id (as-is порядок архивирования склада), удаляемый склад — тоже, если он архивный; под блокировкой — четыре проверки (остаток товара, оборудование, незавершённые документы, последний активный) и UPDATE с условием deleted_at IS NULL; 0 строк → 404 — DS-021, DS-024
    • 27два администратора одновременно удаляют (или один удаляет, другой архивирует) два последних активных склада: ровно один запрос успешен, второй — 409 WAREHOUSE_LAST_ACTIVE (as-is гарантия архивирования сохраняется)
    • 28приход товара, перемещение оборудования на склад, создание документа со складом одновременно с удалением: эти операции проверяют deleted_at IS NULL склада под своей блокировкой — удаление выиграло → 400 warehouse_id: not_found; операция выиграла → удаление видит остаток, оборудование или документ и отказывает
  2. 29Удаление поставщика:
    • 30один UPDATE с условием deleted_at IS NULL; 0 строк → 404 SUPPLIER_NOT_FOUND; создание документа с этим поставщиком, прошедшее раньше, остаётся — документ показывает бейдж (DS-014)
  3. 31Восстановление склада и поставщика:
    • 32один UPDATE с условием deleted_at IS NOT NULL; не удалён → 409 NOT_DELETED; нарушение частичного уникального индекса названия → 409 NAME_TAKEN — DS-017, DS-024
  4. 33Создание и переименование одновременно с восстановлением записи с тем же названием:
    • 34исход определяет частичный уникальный индекс: ровно один запрос успешен; второй — 400 name: duplicate у создания (as-is) либо 409 NAME_TAKEN у восстановления — DS-017
  5. 35Увеличение количества в строке товара заказа одновременно с удалением её склада:
    • 36правка количества читает склад строки под блокировкой и ждёт транзакцию удаления склада: удаление выиграло → 409 WAREHOUSE_DELETED; увеличение выиграло → списанный товар создаёт остаток либо долг, удаление склада видит ненулевой остаток и отказывает (409 WAREHOUSE_IN_USE) — DS-050
