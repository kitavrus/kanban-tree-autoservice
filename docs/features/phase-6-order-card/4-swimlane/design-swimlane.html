Swimlane: Карточка заказа (фаза 6)

Взаимодействие ролей при открытии, редактировании и печати карточки. Роль × 5 фаз работы.

Цели: Пользователь работает с полной карточкой заказа: редактирует шапку (название, описание, клиента, ответственного, сроки, статус оплаты); управляет оборудованием; добавляет услуги и товары из каталога; журналирует работу; печатает акты приёма/выдачи. Система синхронизирует остатки склада при правке списывающей колонки (Reconcile).

Потоки данных и ошибки

1. Открытие карточки (AC-001)
Deep-link ?task=N → GET /api/v1/tasks/:id/card
Данные
  • Request: GET /api/v1/tasks/:id/card
  • Response: OrderCardResponse (7 подзапросов, без N+1)
  • Поля: task (TaskResponse: TaskCard + description_html, paid_at, created_at, updated_at; в т.ч. total_amount, last_log, version), column {id, name, is_final, consumes_stock}, equipment[] {equipment_id, type_name, brand, model, serial, completeness, condition, history[] {task_id, title, created_at}}, subtasks[] {…, products[], logs[] {…, can_edit}}, stock[] {product_id, stock, min_stock, task_reserved}
  • Ошибки: 404 TASK_NOT_FOUND, 401 UNAUTHORIZED
  • См. полный список полей в design-go-layers.md
2. Сохранение шапки (AC-002, AC-003)
PUT /api/v1/tasks/:id → обновление шапки заказа
Данные
  • Request: TaskUpdateRequest (title, description, client_id, column_id, assignee_id, due_date, is_paid, version)
  • Response: 200 TaskMutationResponse {task, warnings} (as-is фазы 5, re-fetch-after-write) → клиент делает GET /api/v1/tasks/:id/card
  • Валидация: description ≤10000 символов, PUT без description не менять
  • Ошибки: 409 TASK_VERSION_CONFLICT, 409 TASK_EQUIPMENT_IN_USE (смена клиента), 403 PAID_ADMIN_ONLY
Блокировки (ADR-100)
  • LockTargetColumn FOR SHARE → LockTask FOR UPDATE → version → paid-гард → ForeignInUse (409) / DeleteForeign → UPDATE tasks (version+1)
  • withTx ретраит 40P01/40001 ×3 (errTaskMovedRetry — только row-мутации услуг/товаров)
3. Добавление оборудования (AC-004, AC-005)
Два запроса: создать в clients, привязать к заказу (ADR-004)
Данные
  • 1. POST /api/v1/clients/:id/equipment (as-is): EquipmentRequest (type_id, brand, model, sku, serial, specs, note) → 201 EquipmentResponse
  • 2. POST /api/v1/tasks/:id/equipment: TaskEquipmentCreateRequest (equipment_id, completeness, condition)
  • Response: 201 {card: OrderCardResponse, warnings}; повтор той же единицы — 201 без изменений
  • Ошибки: 404 TASK_NOT_FOUND; 400 VALIDATION fields[equipment_id] (не найдено / оборудование другого клиента), fields[completeness|condition] ≤1000
  • PUT /api/v1/tasks/:id/equipment/:equipment_id: TaskEquipmentUpdateRequest (completeness, condition); 404 TASK_EQUIPMENT_NOT_FOUND
4. Управление услугами и товарами (AC-007, AC-008, AC-010, AC-014)
POST/PUT/DELETE сервис-строк с синхронизацией склада (Reconcile)
Добавление услуги (AC-007)
  • POST /api/v1/tasks/:id/subtasks: SubtaskCreateRequest (service_id) — price и комплект товаров копирует сервер
  • Response: 201 {card: OrderCardResponse, warnings}
  • Ошибки: 404 TASK_NOT_FOUND, 409 SUBTASK_FINAL_COLUMN, 400 fields[service_id] (не найдена / в архиве)
Редактирование услуги и товаров (AC-008, AC-010, AC-014)
  • PUT /api/v1/subtasks/:id: SubtaskUpdateRequest (status, assignee_id, due_date, price, equipment_id)
  • POST /api/v1/subtasks/:id/products: SubtaskProductCreateRequest (product_id, qty) — цена из products.price
  • PUT /api/v1/subtask-products/:id: SubtaskProductUpdateRequest (qty, price) — qty >0 Scale 9/3, price null|≥0 Scale 10/2
  • Клиент (ADR-105): не более одного PUT на строку в полёте, тело — из последнего card + ожидающих правок
  • Response: 200 {card: OrderCardResponse, warnings}
  • Ошибки: 409 SUBTASK_FINAL_COLUMN (выход из done), 404 SUBTASK_NOT_FOUND/SUBTASK_PRODUCT_NOT_FOUND, 400 fields[status|assignee_id|due_date|price|equipment_id|product_id|qty]
Удаление (AC-007, AC-010)
  • DELETE /api/v1/subtasks/:id: каскадное удаление услуги + товары + логи
  • DELETE /api/v1/subtask-products/:id: удаление товара
  • Response: 200 {card: OrderCardResponse, warnings}
Stock Reconcile (ADR-100)
  • StockEngine.Reconcile(task_id, column.consumes_stock) — при изменении состава товаров: create/delete услуги, create/update/delete товара; PUT /subtasks/:id — без Reconcile, но под теми же блокировками
  • Возвращает warnings[] (negative, below_min) по товарам
  • Блокировки: FOR SHARE columns → FOR UPDATE tasks → subtasks → subtask_products → products
5. Журнал работ (AC-012)
POST /api/v1/subtasks/:id/logs, PUT/DELETE /api/v1/subtask-logs/:id
Данные
  • POST /api/v1/subtasks/:id/logs: SubtaskLogRequest (text: 1..4000 символов)
  • PUT /api/v1/subtask-logs/:id: SubtaskLogRequest (text)
  • DELETE /api/v1/subtask-logs/:id: удаление записи
  • Response: 201/200 {card: OrderCardResponse, warnings}
  • Ошибки: 403 SUBTASK_LOG_FORBIDDEN (не автор, не admin), 404 SUBTASK_LOG_NOT_FOUND, 404 SUBTASK_NOT_FOUND (POST в удалённую услугу), 400 fields[text]
Access Control (ADR-007)
  • user_id → ON DELETE RESTRICT (автор всегда отображается)
  • Каждый может писать свою запись; редактировать только свою или admin
  • last_log видна на карточке доски (LATERAL LIMIT 1)
6. Удаление оборудования (AC-004)
DELETE /api/v1/tasks/:id/equipment/:equipment_id
Данные и ограничения
  • DELETE: удаление единицы из заказа
  • Ошибки: 409 TASK_EQUIPMENT_IN_USE + details.subtasks[] (если выбрано в услугах)
  • Response: 200 {card: OrderCardResponse, warnings}
7. Печать актов (AC-015, AC-016)
GET /tasks/:id/print/:kind → SSR HTML (intake, handover)
Печатные формы (ADR-102)
  • GET /tasks/:id/print/intake: акт приёма оборудования
  • GET /tasks/:id/print/handover: акт выдачи (всё, что в приёме + все услуги со статусом и ценой (SD-009) + товары qty×цена + итог + оплата)
  • Response: 200 HTML (layout print, RequireSSR, no-store для кэша)
  • Реквизиты: из env FIRM_NAME, FIRM_ADDRESS, FIRM_PHONE (пустые → блок опускается)
  • Ошибки: 404-страница StatusPages.NotFound (нет заказа или kind ∉ {intake, handover}); без сессии — редирект на логин (RequireSSR)
Итоги (ADR-005)
  • card.task.total_amount (SQL-агрегат, design-sql.md §Totals Expression); last_log — LATERAL LIMIT 1
  • «По факту» (subtasks.price=NULL): цена работы не входит, товары услуги входят
  • line_total = round(qty × coalesce(price,0), 2)
Ошибки и защита (Codes 16-22)
Новые sentinel-коды фазы 6 (design-errors.md)
404 ошибки
  • SUBTASK_NOT_FOUND (16): услуга не существует или удалена
  • SUBTASK_PRODUCT_NOT_FOUND (17): товар услуги не найден
  • SUBTASK_LOG_NOT_FOUND (18): запись журнала не найдена
  • TASK_EQUIPMENT_NOT_FOUND (19): оборудование не в заказе
409 ошибки (конфликты)
  • TASK_EQUIPMENT_IN_USE (20): оборудование выбрано в услугах → details.subtasks[] (id, service_name, status)
  • SUBTASK_FINAL_COLUMN (21): финальная колонка запрещает добавлять услуги и выводить из done
403 ошибки (доступ)
  • SUBTASK_LOG_FORBIDDEN (22): только автор или admin могут менять запись журнала
  • PAID_ADMIN_ONLY (11, as-is): смена is_paid только админом
Версионирование и concurrency (ADR-002)
Row-мутации НЕ инкрементируют tasks.version (LWW для строк)
Данные
  • Мутации шапки: version check → инкремент → 409 TASK_VERSION_CONFLICT
  • Row-мутации (услуги, товары, оборудование, журнал): БЕЗ версии → LWW (последнее писание)
  • Строки имеют: subtasks.updated_at, subtask_logs.updated_at, subtask_products (нет updated_at, но есть position для порядка — ADR-103)
  • Блокировки: услуги/товары — columns FOR SHARE → LockTask; оборудование — LockTask; журнал — без блокировки заказа; клиент — очередь PUT на строку (ADR-105)
