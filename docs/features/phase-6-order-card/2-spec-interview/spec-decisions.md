## Зафиксировано без вопросов (эталон prototype/index.html + D-решения)
- Комплектность/состояние — два свободных текстовых поля на `task_equipment` (схема фазы 5: `completeness`, `condition` text; prototype:1103-1104).
- История заказов по единице — строка «Уже был в ремонте: #N …» под единицей оборудования в карточке (prototype:1106).
- Цены работы/товара в заказе правит любой пользователь, включая исполнителя (source: D3, D19).
- Подсказка остатка (prototype:1169-1173): `avail = products.stock + списано этим заказом (task_stock.qty)`, `need = Σ qty товара по всем услугам заказа`; `need > avail` → «в наличии только X», `avail − need ≤ min_stock` → «останется X — минимум M», иначе «в наличии X».
- Итог = Σ цен работ + Σ qty×price товаров; пустая цена работы = «по факту», в сумму не входит (source: D3).

## Батч 1 (Фаза 1 — PRD + границы фазы) — закрыт

### SD-001 (В-1): Рамка PRD
**Решение: a.** Боль — вне системы: принятое оборудование, услуги, товары, ход работ, сумма, акты. JTBD — приём техники →
оборудование с состоянием → услуги с комплектами → журнал работ → итог → печать актов. Метрики: 100% новых заказов
с услугами в карточке за 2 недели; 0 расхождений остаток vs журнал после правок товаров в списывающей колонке;
сохранение карточки p95 < 500 мс. Non-goals: вложения (D21), уведомления, отчёты, серверный PDF, DnD услуг.

### SD-002 (В-2): Где открывается карточка
**Решение: a.** Большая модалка поверх доски (эталон prototype:1007), расширение `openTaskForm`;
deep-link `/board?task=ID` открывает модалку заказа.

### SD-003 (В-3): Модель сохранения
**Решение: a (смешанная).** Шапка (описание, клиент, колонка, ответственный, срок, оплата) — «Сохранить» →
`PUT /tasks/:id` c `version` (D28). Услуги / товары / оборудование заказа — немедленно при изменении строки,
свои эндпоинты, LWW без version (D28); правка товаров в списывающей колонке → сразу `StockEngine.Reconcile`
(D17/D34). Журнал — `POST/PUT/DELETE /subtask-logs` (D27).

### SD-004 (В-4): Акты приёма/выдачи
**Решение: a.** SSR-страницы `/tasks/:id/print/intake` и `/tasks/:id/print/handover`, новая вкладка, `window.print()`
(PDF — браузером, D20). Приём: шапка фирмы, №/дата, клиент (имя, телефон), оборудование (тип, бренд/модель,
серийный №, комплектность, состояние), описание неисправности, подписи «Сдал/Принял». Выдача: + услуги с ценой,
товары qty×цена, итог, статус оплаты, подписи «Выдал/Получил». Фирма — env `FIRM_NAME/FIRM_ADDRESS/FIRM_PHONE`, без UI.

**PRD Review:** одобрен пользователем 2026-09-27.

## Батч 2 (Фаза 2 — Tech Spec) — закрыт

### SD-005 (В-5): Удаление связанных строк
**Решение: a.** Удаление услуги — после `KT.uiConfirm`, каскадом товары + журнал; в списывающей колонке → `Reconcile`
(возврат `task_return`). Удаление единицы оборудования из заказа при наличии услуги с этим `equipment_id` →
409 `TASK_EQUIPMENT_IN_USE` с перечнем услуг.

### SD-006 (В-6): Создание нового заказа
**Решение: a.** Новый заказ: шапка → «Сохранить» (`POST /tasks`) → модалка остаётся открытой в режиме правки `#N`;
разделы оборудования/услуг до первого сохранения заблокированы с подсказкой «сохраните заказ».

### SD-007 (В-7): Исполнитель услуги
**Решение: a.** Любой активный пользователь (включая admin), тот же список, что для ответственного. Заблокированный
остаётся на назначенных услугах с пометкой «неактивен», повторно не выбирается (валидатор: новый/изменённый
`assignee_id` → только активный).

### SD-008 (В-8): Триггер сохранения строки
**Решение: a.** По `change` (blur/Enter для чисел и текста, сразу для select/checkbox/статуса); один запрос = один
`Reconcile`; строка блокируется на время запроса; ошибка → откат значения + сообщение.

**Tech Spec:** `output.md` записан 2026-09-27; батч 3 не понадобился — остаток открытых мест вынесен в Q-001…Q-007 для design.

## Design Review (фаза 3) — решения пользователя

### SD-009: Состав акта выдачи
**Решение (подтверждено пользователем 2026-09-27 через оркестратора, design-review фазы 6):** акт выдачи
перечисляет **все** услуги заказа со статусом (не только выполненные) с ценами, товары qty×цена; итог акта = итог
карточки (`task.total_amount`, AC-013). Уточняет формулировку AC-016 «выполненные услуги». Driver: AC-016. Ссылка: ADR-102.
