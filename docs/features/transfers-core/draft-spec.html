§1. Суть задачи

Перемещение между складами становится общим документом для товаров и оборудования клиентов; местоположение оборудования переезжает со строки заказа на саму единицу. Для администратора; исполнитель видит результат в карточке заказа и на доске.

Бизнес (что делает пользователь/процесс):

  1. 1Администратор создаёт документ «склад → склад» со строками двух видов: товар (количество) и единица оборудования клиента (§8.1) — DS-001, DS-010.
  2. 2Отправляет, принимает (товар — с фактом), отменяет документ — три шага, как у перемещения товаров сейчас (§5).
  3. 3В карточке заказа любой пользователь видит, где единица: «у клиента» / «на складе X» / «в пути → Y», и ссылку на документ (§8.2) — DS-003, DS-008.
  4. 4Доска фильтруется по складу и показывает бейдж «в пути» по новому местоположению — DS-046.

Логика (правила системы):

  1. 5Один документ со смешанными строками; вторая сущность не заводится — DS-001.
  2. 6Строка-единица — только оборудование клиента (equipment.client_id NOT NULL); «наше оборудование» — товар каталога с количеством — DS-005, DS-009, DS-010.
  3. 7Местоположение — одно на единицу: at_client, at_warehouse, in_transit; меняется только документом (и добавлением единицы «у клиента» в заказ с выбором склада приёма — временно, до части 4) — DS-008, DS-003.
  4. 8Единица — только в одном незавершённом документе (заявка или в пути); занимается при добавлении в заявку — DS-019, DS-041.
  5. 9Отправить единицу можно только со склада, где она числится — DS-036.
  6. 10Единицы принимаются целиком вместе с документом; факт вводится только по товарам — DS-037.
  7. 11Единицу в незавершённом документе нельзя убрать из заказа; единицу со строками документов нельзя удалить из справочника; склад с оборудованием или незавершёнными документами нельзя архивировать — DS-026.
  8. 12Время: хранение UTC (timestamptz); показ — как на остальных экранах проекта на момент мержа (после части 2 user-timezone — по поясу пользователя; DS-031 — контекст, реализуется в user-timezone). Фильтров по датам в этой части нет.
  9. 13Конкурентный доступ (краткий дубль §3):
    • 14правка и переходы документа → optimistic lock version + 409 — DS-048;
    • 15остатки товара → FOR UPDATE строк product_stock в порядке (product_id, warehouse_id) — DS-048;
    • 16занятие единицы документом → guard-UPDATE active_transfer_id IS NULL — DS-041;
    • 17смена местоположения → guard под FOR NO KEY UPDATE (as-built, D75; не FOR UPDATE) строки equipment — DS-036.

Техника (API/данные/интеграции):

  4. 21Новый GET /api/v1/equipment — поиск единиц для строки документа — DS-057.
  5. 22Удаляются POST /api/v1/tasks/:id/equipment/:equipment_id/send, …/receive, …/cancel-transit — DS-003.

Конкурентность (К-3 — по операциям):

  2. 40Остатки товара (send, receive, cancel):
    • 41Lock Order: transfers FOR UPDATE → строки product_stock FOR UPDATE в порядке (product_id, warehouse_id) — as-is D50, DS-048

  3. 43Занятие единицы оборудования документом (create, update):

    • 45Lock Order: после product_stock — строки equipment FOR NO KEY UPDATE в порядке id
    • 46as-built (D75): FOR NO KEY UPDATE, а не FOR UPDATE — вставка строки документа держит на единице FOR KEY SHARE, иначе параллельные создания взаимно блокируются; общий порядок блокировок: документ → заказ (FOR KEY SHARE, с части 4 — при создании/правке документа с клиентом) → product_stock → equipment

§6. API

Режим B «API + фронтенд». Базовый URL стенда: http://localhost:8080. Авторизация — сессионная cookie sid (плейсхолдер <SID>). Копируй curl в терминал или в Postman: Import → Raw text. Тело ошибки — формат pkg/errorspkg: {code, message, details}; при 400 — details.fields[] с name и message. Ключи — snake_case, URL — kebab-case (CLAUDE.md §API-1). Коды ошибок переименованы: STOCK_TRANSFER_NOT_FOUND → TRANSFER_NOT_FOUND, STOCK_TRANSFER_VERSION_CONFLICT → TRANSFER_VERSION_CONFLICT, STOCK_TRANSFER_STATUS_CONFLICT → TRANSFER_STATUS_CONFLICT. as-built (D76, D80): количества (qty_sent, qty_received, warnings[].stock, warnings[].min_stock) — JSON-числа в запросе и в ответе, не строки. Текстовые поля с недопустимыми символами (например NUL в note) → 400 invalid_text. Текст 403: в этой части API закрыт общим admin-only middleware — сообщение admin only; с части 4 исполнитель допущен к документам с клиентом, собственные отказы сервиса перемещений — «Нет доступа».
