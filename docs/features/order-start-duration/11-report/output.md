# Отчёт: order-start-duration — «Начать с» + «Дней на работу»

## Что сделано

Ручной «Срок» заказа заменён двумя полями: `start_date` («Начать с») и `duration_days`
(«Дней на работу», 1–60). `due_date` теперь вычисляемая колонка — плановое окончание,
`start_date + duration_days − 1`. От него работают метка 📅 и фильтр «Горит/просрочено» на
доске.

Календарь загрузки и диаграмма Ганта считают занятость с `start_date` по плановое окончание.
Выданный заказ занимает место по день выдачи. Заказ, выданный раньше начала, место не
занимает. Невыданный просроченный стоит до выдачи. Окно нового заказа и шапка карточки
показывают оба поля и плановое окончание. Подсказка о загрузке и предупреждение «нет
свободных мест» считаются по плановым дням. Оба поля правятся в карточке. `due_date` во
входе API даёт 400.

Миграция 0018 заполняет старые заказы:
- начало = день приёмки (Asia/Almaty);
- дни — до прежнего срока, не больше 60;
- открытым без срока — до дня миграции;
- выданным без срока — 1.

Демо-сид переделан под одну машину на заказ и новые планы. Dev-БД снесена и залита заново.

## Known issues / as-is

- Кламп 60 дней в бэкфилле:
  - прежний срок дальше 60 дней укорачивается, и откат вернёт укороченный срок;
  - открытый заказ без срока, принятый больше 60 дней назад, станет «просроченным».

  На текущей dev-БД (свежий сид) таких заказов нет.
- Тип `DueDate *string` в DTO оставлен nullable, хотя NULL не бывает: wire-контракт as-is.
- Фикстура e2e `createTask` по умолчанию ставит план «сегодня, 1 день», поэтому все
  фикстурные заказы попадают в «Горит». Фильтр покрыт отдельным PLAN-003 с явными планами.
- В Docker висят 8 чужих контейнеров `redis:7-alpine` от 12.10 — не тронуты.
