## Модель предметной области (кратко, детали — plan.md §3)
Заказ (task; **статус = колонка**, цвет карточки = цвет колонки; оплачен/не оплачен; ответственный; срок)
→ **Принятое оборудование клиента** (реестр у клиента: тип, производитель, модель, артикул, SN/VIN, характеристики по шаблону типа; в заказе — комплектность и состояние при приёмке; история ремонтов)
→ **Услуги** (подзадачи = услуги из каталога; статус new/in_progress/done вручную; исполнитель; срок и цена необязательны; привязка к единице оборудования или «к заказу в целом»; **журнал работ**)
→ **Товары** внутри услуги (комплект из каталога, qty × price правятся).

Правила: в финальную колонку нельзя, пока не все услуги done (D11, 409); цены копируются в заказ; роли admin / executor.

**Новое после прототипа (2026-09-25):**
- D16 — названия категорий каталога уникальны в пределах вида (без учёта регистра/пробелов).
- D12/D17 — у товара остаток, **минимальный остаток**, коробка, место хранения (строки). Товары заказа **списываются**, когда заказ попадает в колонку с `consumes_stock` (по умолчанию «В работе» и дальше; заказ согласован с клиентом). Правка товаров в заказе — дописание/возврат разницы; возврат заказа в колонку без списания или удаление — товары на склад. **Уход в минус разрешён** (предупреждение, не блок). Журнал `stock_movements` (в т.ч. `manual` при правке остатка в карточке товара). Отдельной операции «приход/корректировка» — **не делать**.
- D18 — после списания предупреждение о товарах ≤ минимума; подсказки наличия в карточке заказа; экран **«Остатки»** (виден всем, правка — admin): KPI, рисковые товары, прогноз с учётом ещё не взятых в работу заказов, счётчик в меню.

## Стек и решения по реализации
- Go (Fiber v3, pgx/v5, golang-migrate, go-redis), PostgreSQL 18, Redis 7, docker-compose для локального стенда.
- Авторизация — **сессия** (cookie `sid` HttpOnly + Redis), CSRF, bcrypt; роли admin/executor.
- Фронтенд — **Go `html/template` + чистый JS, без Vue/React и без сборщика**. Доска, карточка заказа и «Остатки» — «rich» (свой JS поверх JSON API); справочники (клиенты, каталог, сотрудники) — простые SSR-CRUD.
- Go-модуль: `github.com/kitavrus/kanban-tree`, HTTP-порт 8080.
- Каркас — через `/project-bootstrap` (manifest: `auth.mode=session`, `components.frontend=false`). ⚠️ Скрипт **перезаписывает `CLAUDE.md` и `.gitignore`** — перед запуском сделай их копии и после генерации объедини (моё содержимое сохранить целиком, строки каркаса дописать в конец). `CLAUDE.md` и `.idea/` — мои неотслеживаемые файлы, не коммитить.
- Фичи — через скаффолдеры из глобального CLAUDE.md; для SSR-справочников подходит **`/z-scaffold`** (Go html/template + vanilla JS). Rich-экраны (доска, карточка заказа, остатки) — руками поверх JSON API; если видишь вариант лучше — предложи.
- Действуют мои глобальные правила: Testing doctrine (TD-1…TD-8, EE), API-1, GO-1, SS-1, TM-1, CM-1 (**режим MVP** — прода нет), US-1.
